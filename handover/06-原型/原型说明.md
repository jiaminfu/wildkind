# 原型说明

> 这份文档解释**原型怎么看、每个页面在做什么、点哪里会发生什么**。
> 前台（买家看到的商店）和后台（你运营用的控制台）都在这里。
> 最后更新：2026-11-13 · 版本 v1.1 · 截图与代码同一版本

**v1.1 变更**：后台从 10 个模块扩到 **13 个**（补集合 / 内容 / 定制需求单，FRD 第 48 行要求但此前漏做）；后台表格在窄屏改为卡片化；旧原型（4500）的后台已下线并指向交付版。

## 一、先说清楚：现在有两套东西

| | 旧原型（只留前台） | **交付版（以此为准）** |
|---|---|---|
| 地址 | `http://localhost:4500` | **`http://localhost:4600`** |
| 目录 | `prototype/` | `app/web` + `app/server` |

## 二、怎么启动

```bash
# 生成演示数据（只需一次；重跑会覆盖）
node app/server/seed.js

# 起服务（API + 静态前端同端口）
node app/server/index.js           # → http://localhost:4600
```

想反复跑测试，必须带复位开关，否则第二遍会撞上一遍留下的数据和限流：

```bash
ALLOW_TEST_RESET=1 node app/server/index.js
curl -X POST http://127.0.0.1:4600/api/v1/__test/reset
```

> 复位只还原**业务数据**，不动 `sessions`（会话）。早期版本连会话一起回滚，结果是"你在浏览器里点一下菜单就被踢回登录页"——因为令牌对应的会话已经被测试脚本清掉了。这个坑已修，并写进了回归脚本。

### 新增：定制需求 `#/custom`

页脚「Custom orders」进来。表单只强制两栏：**邮箱 + 需求描述**，其余（款式、数量、期望交期、参考图链接）都是加分项。

- 提交走 `POST /api/v1/custom-requests`（公开端点，限流 6 次 / 10 分钟）
- 成功页给出单号 `CR1001`，同一编号在后台 `#/admin/custom` 里能看到
- 参考图链接只收 `http(s)`，最多 5 条，其余静默丢弃（不做报错，避免因为一条脏链接丢掉整张单）

> 为什么不收集支付信息：定制件没有固定 SKU，报价要人算。先收线索、再报价、最后成单，是这个生意真实的顺序。

### 4 集合 `#/admin/collections`（新增）

**看什么**：一共几个集合、几个挂在导航上、几个是空的。

**能做什么**：改标题与描述、改排序、**一键开关导航**（列表里直接点 Show/Hide，不用进详情）、新建、删除。

**关键约定**：集合没有自己的商品表，它就是商品身上的 `collections` 数组。所以「商品数」永远现算——存一份冗余计数，迟早和商品对不上，后台显示 12 件、前台打开只有 10 件，是最难查的一类不一致。

**为什么删不掉某些集合**：里面还有商品时拒绝删除（409 `COLLECTION_NOT_EMPTY`）。删掉集合后商品会从那个入口静默消失，运营很难把两件事联系起来。要求先移空，是故意制造的一点不方便。

### 8 定制需求单 `#/admin/custom`（新增）

**看什么**：多少单在等报价、已报价几单、已成几单。

**能做什么**：按状态筛选、进详情填报价与内部备注、推进状态 `New → Quoted → Ordered → Closed`。

**关键约定**：状态**单向**。跳步或回退返回 409 `BAD_TRANSITION`，提示里列出当前允许的目标状态。回退会让运营对一个已经报过价的单子重报一次，比不能回退更糟。

### 10 内容 `#/admin/content`（新增）

**看什么**：首页文案（品牌名、slogan、公告栏、Hero 眉标/标题/正文、Best sellers 眉标）+ 12 个内容页的标题与导语。

**能做什么**：改完保存，前台刷新即变。公告栏用 `|` 分隔多条，Front 会逐条轮播；Hero 标题用 `|` 断行（前半常规、后半斜体）。

**边界写死在这里**：**正文段落不在这个模块里**，仍在 `app/web/assets/js/pages.js`。这一版刻意不做富文本——没有预览与版本对比的富文本编辑器，改坏了只能回滚代码。页面底部原文写着这句，不让人误以为改完没生效。

### 2 订单 `#/admin/orders`

**看什么**：按状态分 tab（All / Paid / Preparing / Shipped / Refunded），每行显示单号、客户、状态、件数、金额、时间。

**能做什么**：搜索单号/邮箱/姓名；点整行进详情。

**关键约定**：**点整行进详情**（`data-act="open-order"` 挂在 `<tr>` 上）。订单号含 `#`，路由里必须编码，解析时必须解码——不解码就变成 `%23TG1041` 再被编码一次，接口报 `Order not found`，表现是"点开订单详情打不开"。这条已经踩过，回归脚本 `admin-sweep.js` 守住了。

### 3 商品 / 5 库存 / 11 流水：三者是同一条链

- 商品页改价 → 前台立即变（服务端定价，前端价格字段一律丢弃）
- 库存页看「在库 / 占用 / 可售」，低于安全库存进预警区
- 流水页是**只追加**的账：每次变动记一条，硬判据是「末条 `balanceAfter` = 当前库存」。对不上就说明有人绕过了流水入口

### 12 审计 / 13 设置

- 审计：登录、改价、改库存、改状态、删评价、改活动、改内容，都留痕，按域分组
- 设置：免邮门槛、标准/快递运费、赠品门槛、安全库存、公告栏、接单开关。改完只影响**之后**创建的订单（费率快照），历史订单金额与毛利一分不变

## 五、走一遍：买家 9 步（约 3 分钟）

1. `#/` 首页 → 点 Best Sellers 里任一商品
2. 详情页 → 选 Silver、尺寸 18" → 加购 → 右侧抽屉滑出，显示免运进度
3. 继续逛，再加一件（凑过 $120 会送 Pearl Studs）
4. 点抽屉里的 Checkout → 进 `#/cart`
5. 调数量 → 去结算
6. 填邮箱（试试全大写，后面查单仍能查到）、地址、选 Express
7. 点 Pay → 成功页，记下订单号 `#TG…`
8. 回 `#/account/lookup` 用「订单号 + 邮箱」查这笔单
9. 去 `#/custom` 提交一张定制需求单，记下 `CR…`，下一步在后台找它

**中途可以验证的坑**：结算页把浏览器后退再前进，订单不会重复创建（`Idempotency-Key` 生效）；改一下购物车里的价格再提交，会被服务端拒绝（`PRICE_CHANGED`）。

## 六、走一遍：运营 10 步（约 5 分钟）

1. `#/admin` 登录 → 看板四个 KPI 与三件待办
2. 「Reviews to moderate」→ 把一条 pending 评价 Approve → 回该商品页，评价出现在列表里
3. `#/admin/orders` → **点整行**进详情 → 推进到 Shipped → 填运单号
4. 同一单点 Refund → 回库存看是否 +1，回 `#/admin/ledger` 找那条 `refund` 流水
5. `#/admin/coupons` → 新建 `TEST10`（10% off）→ 回前台加购 → 结算页输入 `TEST10` → 价格立刻减 10%
6. 回后台删掉 `TEST10` → 前台再试同一张券 → 下单被拒 `COUPON_INVALID`
7. `#/admin/collections` → 把 `SALE` 的导航关掉 → 回前台看顶部菜单里它消失
8. `#/admin/content` → 把 Hero 标题改成 `Sea glass doesn't fade.|Say it with steel.` → 回首页看首屏
9. `#/admin/custom` → 找到第 9 步提交的 `CR…` → 填报价 180 → 推进到 Quoted
10. `#/admin/settings` → 免运门槛改成 120 → 回前台购物车看进度条变化

## 七、双端适配

**断点**：1440 桌面基准 / 1180 折叠双栏 / 900 后台侧栏收成抽屉 / **620 后台表格折成卡片**

**实测**：13 个后台模块 + 12 个前台页面 × 390 / 768 / 1440，**全部无横向溢出**，0 个 console error。

后台移动端不是把桌面版缩小，做了四件事：

1. **侧栏 → 抽屉**：汉堡按钮开合，桌面宽度下自动隐藏按钮
2. **KPI 4 列 → 2 列 → 奇数末张横跨整行**（三张卡时右边不会空一格）
3. **表格 → 卡片**：≥4 列的表在 ≤620px 时把整行折成卡片，列名由 `data-l` 显示在值左侧
4. **顶栏减负**：手机上隐藏「View store」与账号名，只留汉堡、标题、退出

关于第 3 条，为什么不选横向滑动：宽表在手机上滑动时，**金额和日期恰好藏在最右两列**，而这两个字段正是运营在手机上最需要看的。折成卡片虽然更高，但每一条都完整。

实现方式：渲染后按 `thead` 自动给每个 `td` 打 `data-l`（`app.js` 的 `labelTables()`），改表头不需要改 CSS。单元格内容会被包一层 `.tdv`——不包的话，`<姓名><br><邮箱>` 在 flex 布局里会摊成一行，邮箱直接顶出屏幕。

**图标**：所有内联 svg 都显式给宽高。只写 `viewBox` 的 svg 在 flex 容器里会塌成 0 或被渲染成 300×150，表现为「按钮有框、里面空白」。

复跑命令：

```bash
node tools/app-check.js                                  # 66 / 66（18 路由 × 3 宽度 + 关键元素）
node tools/admin-sweep.js http://localhost:4600 390      # 13 模块真实点击 + 溢出 + 报错
node tools/shot-doc.js <目录> --only=store --w=1440|390  # 前台整页截图
```

## 九、原型的边界（它不做什么）

| 不做 | 现在是什么 | 什么时候做 |
|---|---|---|
| 真实扣款 | 支付框是 Stripe 测试模式提示，点 Pay 不走真实通道 | 你给 Stripe 密钥之后 |
| 真实发信 | 邮件模板已设计，但发送走的是日志 | 你给 Resend API Key + 验完发信域名 |
| 真实物流 | 运单号可以填，但不会回调物流商接口 | 3PL 对接方式确定后 |
| 内容页正文编辑 | 后台只能改标题与导语，正文在 `pages.js` | 下一版（需要预览 + 版本对比） |
| 定制单自动报价 | 报价人工填，不测算工时与材料 | 有意不做：定制件 SKU 不固定，自动报价会给错价 |
| 商品图分金属 | 一个商品一套图，色点只做展示 | 补齐素材后恢复卡内切换 |
| SEO / SSR | 纯静态 SPA + hash 路由，搜索引擎抓不到商品页 | **上线前必须改**，这是已知硬伤 |

最后一条要特别注意：**hash 路由（`#/products/xxx`）对 SEO 是致命的**。原型阶段无所谓，正式站必须换成真实路径 + 服务端渲染或预渲染。这件事已经记在 SDD 的演进路线里，不在这里偷偷跳过。
