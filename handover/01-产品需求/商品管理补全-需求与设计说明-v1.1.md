## 1. 问题陈述

后台 `Catalog → Products` 目前只有两个动作，无法支撑 100 款 SKU 上架。

| 能力 | 现状 | 证据 |
|---|---|---|
| 改价 | ✅ 有 | 行内 `Price` 按钮，弹窗输入，带 version 乐观锁 |
| 上架 / 下架 | ✅ 有 | 行内 `Publish` / `Unlist`，写 `active` 字段 |
| 补库存 | ✅ 有 | `Inventory` 页 `+20`，写 `stockLedger` 流水 |
| 改标题 / 描述 / 徽章 / 集合 | ⚠️ 后端有、界面无 | `PATCH /admin/products/:id` 已处理 `title`/`desc`/`badge`/`compareAt`/`cost`/`collections`，前端未提供表单 |
| 新建商品 | ❌ 无 | 后端无 `POST /admin/products`，前端无按钮 |
| 换图 / 传图 | ❌ 无 | 图片是 `assets/img/opt/*.jpg` 静态文件，只能改代码 |
| 增删变体（颜色 × 价格 × 库存） | ❌ 无 | `PATCH` 不处理 `variants` |
| 删除商品 | ❌ 无 | 无 `DELETE`，只能下架 |

**影响**：新品上架必须改 `seed.js` 或直接编辑 `db.json` 后重建容器，等于每个新品都要动服务器。这是当前最卡运营的一处缺口。

---

## 2. 目标

> 店主不碰代码、不碰服务器，在浏览器里完成「新建商品 → 传图 → 设变体与库存 → 上架」全流程，单款 3 分钟内完成。

同时不破坏三条既有约束：成本价不出公网、下架即刻对前台不可见、所有写操作进审计日志。

## 3. 需求清单（EARS）

优先级：🔴 阻塞上架 ｜ 🟡 强烈建议 ｜ 🟢 可选

### A. 新建商品

**PM-01** 🔴 When 有 `products:write` 权限的店员提交新商品表单，the system shall 创建一条商品记录并以 `active=false`（草稿）保存，返回新商品完整对象。
*验收*：Products 列表出现新行，状态列显示 Draft，前台列表与详情均不可见。

**PM-02** 🔴 When 提交内容不合法（标题为空 / 售价 ≤ 0 / 售价比成本低 / handle 重复 / 无任何变体），the system shall 拒绝请求并返回字段级错误，指出具体哪个字段不合法。
*验收*：表单对应字段下方显示错误，已填内容不丢失。

**PM-03** 🔴 When 创建商品，the system shall 自动生成 `id`（`TG-` + 现有最大序号 +1）与 `handle`（标题转 slug），并写入 `createdAt`、`version=1`。
*验收*：连续建 3 款，id 不重复、handle 不重复，`TG-103 / TG-104 / TG-105` 连续。

### B. 编辑商品

**PM-04** 🔴 When 店员在编辑抽屉里保存，the system shall 更新 `title`/`desc`/`cat`/`motif`/`set`/`badge`/`compareAt`/`price`/`cost`/`sizes`/`collections`/`images`/`variants`，并令 `version+1`。
*验收*：保存后前台刷新即可见新内容；旧 version 的并发提交被拒（409）。

**PM-05** 🔴 When 店员修改售价，the system shall 同步按原比例调整各变体价，保持 Gold / Rose Gold 的溢价关系。
*验收*：主价 76 → 80，变体 76 与 82 变为 80 与 86（±0.01 舍入）。

**PM-06** 🔴 When 店员只改标题、未手改 handle，the system shall 保留原 handle 不变。
*验收*：改标题后商品 URL 不变，已投放的外部链接不会 404。

**PM-07** 🟡 When 店员修改 handle，the system shall 校验全局唯一（不得与其它商品 id 或 handle 冲突）。
*验收*：填重复 handle 时保存被拒并提示。

**PM-08** 🟡 When 店员点 `Duplicate`，the system shall 复制该商品为新草稿，标题加 `(copy)`、handle 加 `-copy`、变体库存归零。
*验收*：复制出的草稿不影响原商品，库存流水不复制。

### C. 图片

**PM-09** 🔴 When 店员选择图片文件（JPG/PNG/WebP，单张 ≤ 5 MB），the system shall 在浏览器端等比压缩至最长边 1600 px、质量 0.82，上传后保存到数据卷并返回可访问路径。
*验收*：上传后立即预览；重启容器后图片仍可访问。

**PM-10** 🔴 When 商品已有 6 张图，the system shall 拒绝继续添加并提示「最多 6 张」。
*验收*：第 7 张被拒，前 6 张不受影响。

**PM-11** 🔴 When 店员拖动图片排序或点删除，the system shall 按新顺序更新 `images` 数组，第一张作为前台主图。
*验收*：列表与前台主图随之变化。

**PM-12** 🟡 When 上传成功但商品未保存，the system shall 在 24 小时后清理未被任何商品引用的上传文件。
*验收*：放弃的草稿图片不长期占用磁盘。

### D. 状态与生命周期

**PM-13** 🔴 When 店员点 `Publish`，the system shall 置 `active=true`，前台立即上架；点 `Unlist` 则置 `false`，前台列表不显示、详情 404、加购被拒。
*验收*：两个方向各测一次，含购物车里已存在的该商品。

**PM-14** 🟡 When 店员删除一个**无任何订单引用**的商品，the system shall 硬删除该商品记录，但其历史库存流水保留（`stockLedger` 不删）。
*验收*：删除后列表消失；流水页仍能按 SKU 查到旧记录。

**PM-15** 🟡 When 商品已被订单引用，the system shall 拒绝硬删并提示「该商品有 N 笔订单，只能下架」。
*验收*：删除按钮置灰或点击返回 409，原因可读。

**PM-16** 🟢 When 店员在列表勾选多行，the system shall 支持批量上架 / 批量下架。
*验收*：一次操作 10 款，逐条写审计日志。

### E. CSV 批量导入（v1.1 新增）

**PM-17** 🔴 When 店员上传一份符合模板的 CSV，the system shall 先做**全量预检**（不写库），返回逐行校验结果：可导入 N 行、错误 M 行及每行错误原因。
*验收*：错 3 行时，返回精确到行号与列名的错误，且此时数据库中无任何新增商品。

**PM-18** 🔴 When 预检全部通过且店员点确认导入，the system shall 按行创建商品，全部为 Draft 状态，并在结果里返回每个新商品的 id 与 handle。
*验收*：导入 100 行后列表出现 100 个 Draft，id 连续无重复。

**PM-19** 🟡 When CSV 存在部分错误，the system shall 允许店员选择「只导入正确行」或「全部放弃」，默认必须显式选择，不做静默部分导入。
*验收*：选「只导入正确行」时错误行被跳过并列明；选放弃时库中零变更。

**PM-20** 🟡 When 店员点「下载模板」，the system shall 返回带表头与两行示例的 CSV（UTF-8 含 BOM，Excel 直接打开不乱码）。
*验收*：下载的文件双击打开，中文列名与示例行正常显示。

**CSV 列定义**（一行 = 一个 SKU，同款多金属写多行，靠 `group` 列归并成同一商品的多个变体）：

| 列名 | 必填 | 说明 |
|---|---|---|
| `group` | 🔴 | 同款归并键，相同值的行合成一个商品（如 `moonlit-hare`） |
| `title` | 🔴 | 商品标题，同 group 取第一行 |
| `handle` | 🟢 | 留空自动生成；填了需全局唯一 |
| `category` | 🔴 | necklaces / bracelets / anklets / rings / hair |
| `price` | 🔴 | 主售价，同 group 取第一行 |
| `cost` | 🟡 | 成本价 |
| `compareAt` | 🟢 | 划线价 |
| `metal` | 🔴 | Gold / Silver / Rose Gold |
| `sku` | 🟢 | 留空自动生成 |
| `stock` | 🔴 | 该变体初始库存 |
| `variantPrice` | 🟢 | 该变体单独售价，留空沿用主价 |
| `desc` | 🟢 | 描述 |
| `motif` / `set` | 🟢 | 图案 / 系列标签 |
| `badge` | 🟢 | New / Bestseller |
| `images` | 🟢 | 竖线分隔的图片路径，最多 6 个 |
| `collections` | 🟢 | 竖线分隔的集合 handle |
| `sizes` | 🟢 | 竖线分隔，如 `16"\|18"` |

## 4. 数据模型

沿用现有结构，不新增集合，只补齐字段与约束。注意**内部字段名与前台不同名**（`cat` / `desc`），实现时以内部名为准。

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `id` | string | 自动 | `TG-` + 数字，全局唯一，创建后不可改 |
| `handle` | string | 自动 | 小写字母数字连字符，全局唯一，可改需查重 |
| `title` | string | 🔴 | 1–120 字符 |
| `desc` | string | 🔴 | 1–2000 字符 |
| `cat` | string | 🔴 | 枚举：`necklaces` / `bracelets` / `anklets` / `rings` / `hair` |
| `motif` | string | 🟢 | 图案标签（hare / shell / clover …），用于筛选 |
| `set` | string | 🟢 | 系列标签（woodland / ocean / celestial） |
| `price` | number | 🔴 | > 0，且 ≥ `cost` |
| `cost` | number | 🟡 | ≥ 0，仅后台可见，不出现在任何公开接口 |
| `compareAt` | number\|null | 🟢 | 划线价，须 > `price`，否则拒绝 |
| `badge` | string\|null | 🟢 | `New` / `Bestseller` / null |
| `sizes` | string[] | 🟢 | 如 `16"`, `18"`，最多 5 项 |
| `collections` | string[] | 🟡 | 只接受 `db.collections` 中已存在的 handle |
| `images` | string[] | 🔴 | 1–6 项；新图为 `uploads/<file>`，旧图为 `assets/img/opt/<file>` |
| `variants` | object[] | 🔴 | ≥1 项；`{sku, metal, price, stock}` |
| `variants[].sku` | string | 自动 | 默认 `TG-<id数字>-<金属前两位大写>`，可手改，商品内唯一 |
| `variants[].stock` | number | 🔴 | ≥ 0 整数 |
| `active` | boolean | 自动 | 新建默认 `false` |
| `version` | number | 自动 | 乐观锁，每次写 +1 |
| `createdAt` / `updatedAt` | ISO string | 自动 | 服务端生成 |

**一致性约束**：商品 `stock` 汇总值恒等于 `Σ variants[].stock`，任何变体增删改都必须重算，禁止只改汇总值。

## 5. 接口变更

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/v1/admin/products` | `products:write` | 新建，返回 201 + 商品对象 |
| PATCH | `/api/v1/admin/products/:id` | `products:write` | **扩展**：新增 `images`/`variants`/`sizes`/`motif`/`set` 处理 |
| POST | `/api/v1/admin/products/:id/duplicate` | `products:write` | 复制为草稿 |
| DELETE | `/api/v1/admin/products/:id` | `products:write` | 有订单引用时返回 409 |
| POST | `/api/v1/admin/uploads` | `products:write` | 图片上传，`application/json`，body `{name, dataUrl}` |
| POST | `/api/v1/admin/products/import/preview` | `products:write` | CSV 预检，只返回校验结果不写库 |
| POST | `/api/v1/admin/products/import` | `products:write` | 确认导入，body `{rows, mode}`，`mode=valid-only\|abort` |
| GET | `/api/v1/admin/products/import/template` | `products:write` | 下载 CSV 模板（UTF-8 BOM） |
| GET | `/uploads/:file` | 公开 | 读数据卷里的图片，未命中返回 404（不可走 SPA 兜底） |

**上传为什么不用 multipart**：现有 `readBody` 是 JSON 解析器（上限 256 KB），写 multipart 解析器约 60 行且易出错。改为前端 Canvas 压缩后转 base64 走 JSON，图片实际 200–400 KB、base64 约 300–550 KB，仅对 `/admin/uploads` 单独放宽到 8 MB，其余接口维持 256 KB 不变。

**上传落点**：`/app/app/server/data/uploads/`（已挂 `tideglass-data` 卷，容器重建不丢）。文件名 `p-<时间戳>-<随机6位>.<ext>`，服务端校验扩展名白名单 + 首字节魔数，不接受 SVG（防 XSS）。

**审计**：`product.create` / `product.update` / `product.delete` / `product.duplicate` / `upload.image`，记录变更前后差异（价格、成本、active 至少三项）。

## 6. 前端交互

**Products 页改动**

- 面板头部：标题右侧加 `New product` 主按钮；搜索框保留。
- 表格行内按钮由 2 个变 4 个：`Edit` ｜ `Price` ｜ `Publish`/`Unlist` ｜ `⋯`（菜单：Duplicate、Delete）。
- 状态列沿用 `Live` / `Draft` 胶囊。

**编辑抽屉（新增）**

桌面端右侧滑出 520 px，移动端全屏。三段折叠，一次只展开一段：

1. **Basics**：标题、描述（多行）、品类下拉、系列 / 图案、徽章、售价、划线价、成本、尺码多选、所属集合多选。
2. **Images**：6 格栅格，点击空格选文件、已有图悬停出「删除 / 设为主图」，支持拖拽换序。
3. **Variants & stock**：表格 `金属 | SKU | 单独售价 | 库存`，末行 `+ Add variant`，删除变体需二次确认（提示会丢失该 SKU 的未发货订单关联检查）。

底部固定 `Save` / `Cancel`；有未保存改动时点 Cancel 或按 ESC 弹确认。

**状态流转**

```
（新建）→ Draft ──Publish──→ Live
            ↑                 │
            └─────Unlist──────┘
```

Draft 状态在前台完全不可见（列表过滤、详情 404、加购拒绝），与现有下架逻辑一致。

## 7. 权限与审计

- 新建 / 编辑 / 删除 / 上传均要求 `products:write`（owner 具备；ops 不具备，只读）。
- 成本价 `cost` 仅在 `products:write` 的接口返回中出现——需在 `GET /admin/products` 上再加一层：ops 角色返回 `cost: null`。
- 所有写操作必须进 `auditLog`，与现有 `product.update` 保持一致格式。

## 8. 验收标准

1. 新建一款商品（含 2 个变体、3 张图），全程不碰服务器，3 分钟内完成。
2. 新建后为 Draft，前台搜不到；点 Publish 后前台可搜到、可加购、可结账。
3. 改标题后 URL 不变；改售价后变体价按比例跟随。
4. 上传 6 张图成功，第 7 张被拒；重启容器后图片仍可访问。
5. 删除无订单商品成功；删除有订单商品被拒并给出订单数。
6. ops 账号访问 Products 页看不到成本列，调用写接口返回 403。
7. 所有写操作在 Audit log 页可查到，含操作人与时间。
8. 用模板 CSV 导入 100 行：预检返回 100 行通过，导入后 100 个 Draft，id 连续；故意留 2 行错价，预检精确报行号。
9. `tools/api-test.js` 全量回归通过（当前基线 121 条，本次预计新增 15–20 条）。

## 9. 待确认问题（已于 2026-11-14 全部确认）

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 新建商品默认草稿还是直接上架？ | **默认草稿**（`active=false`），填完再手动 Publish。防止半成品被顾客看到或下单。 |
| Q2 | 变体的「金属」是固定枚举还是自由填？ | **固定枚举**：Gold / Silver / Rose Gold。自由填会污染前台筛选与 SKU 命名。 |
| Q3 | 图片上限 6 张、单张 5 MB 够不够？ | **6 张 / 5 MB**。前端压缩至最长边 1600 px、质量 0.82。 |
| Q4 | 成本价 `cost` 对 ops 角色隐藏，可以吗？ | **隐藏**。ops 调用 `GET /admin/products` 时 `cost` 返回 `null`。 |
| Q5 | 删除策略：无订单才可硬删，接受吗？ | **接受**。有订单引用时返回 409，提示只可下架。 |
| Q6 | 100 款 SKU 手工录还是先要 CSV 导入？ | **本期一起做 CSV 导入**（PM-17~PM-20），首批 100 款用表格批量灌入。 |
