## 3 本轮已修的 12 处

### 3.1 对外承诺与死链

| 改了什么 | 之前是什么样 | 为什么必须改 |
| --- | --- | --- |
| 页脚社交图标改为 `settings.socials` 驱动，**没配就不渲染** | 三个图标全部指向 `/#/pages/about` | 点得开，但不是它说的那件事。访客点一次 Instagram、落到一段品牌故事上，会顺手记住「这站不太靠谱」。现在后台「Settings → Social links」填 URL 才出现 |
| Cookie 条「Learn more」→ 隐私政策 | 指向 About | 同意条必须能打开它让你同意的那份文件 |
| 删除 `#/pages/journal` 的三段占位正文 | 里面写着「**回执见 newsletter**」 | 全站没有 newsletter。这句是真话的反面，且它所在的那条路由现在是死代码（已 301 到 `/journal`） |

### 3.2 首屏与 SEO

| 改了什么 | 数据 |
| --- | --- |
| 首页补 canonical / OG / Twitter / Organization JSON-LD | 之前一条 OG 都没有，转发出去是裸链接 |
| `admin.js`（80,520 B）+ `blog-admin.js`（12,499 B）改为按需加载 | 首屏 JS 从 344,099 B → **251,092 B（−27%）**；实测首屏对 `admin.js` 的请求数为 **0** |
| 版本号由服务端注入 `window.LG_ASSETS` | 按需加载如果前端自己拼路径，会绕过 `?v=` 拿到浏览器里的旧副本——表现是「发了版但有人还在跑旧后台」 |
| `headStatic()` 同步剥掉 canonical / og / twitter / ld+json | 不剥的话 `/journal` 会同时出现首页和文章两套 `og:url`，抓取方取后者 → **一篇讲 PVD 的文章在社媒上预览成首页** |
| 设了 `PUBLIC_URL` 时首页 canonical 跟着变 | 否则首页写 `https://`、文章页按请求算成 `http://`，爬虫当两个站 |

> OG 图片目前用 820×820 的 `c-ocean.jpg`，所以声明的是 `summary` 卡而不是 `summary_large_image`
> （后者要 1.91:1 的 1200×630）。**声明一个尺寸对不上的卡片类型，平台会自己裁，构图是随机的，比不给图更难看。**
> 需要一张 1200×630 的专用素材，已加入《外部资料需求清单》。
