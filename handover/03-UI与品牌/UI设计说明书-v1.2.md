## 1 设计原则

上一版界面被判"太乱"，根因不是配色或审美，是**没有刻度**：全站用过 36 种字号（8px 到 72px，其中 9.5/10/10.5/11/11.5/12/12.5px 各出现二十多次）、间距随手写、容器层级混乱。没有刻度，每个区块看起来就像不同人做的。

这一版只立四条规则，全部可量化：

| # | 原则 | 具体约束 | 违反时的表现 |
| --- | --- | --- | --- |
| 1 | **一把尺子** | 字号只用 8 级，间距只用 8px 基数，字体只用 2 族 | 页面"看起来乱"但说不出哪乱 |
| 2 | **三层容器** | 页面底（cream）→ 内容面（paper）→ 强调块（sea），不允许第四层 | 区块之间没有边界，用户不知道哪里是新的一段 |
| 3 | **一个页面一个主角** | 每屏只有一个元素可以用最大字号或最深色块 | 所有东西都在喊，等于没人被看见 |
| 4 | **克制用色** | Clay 红只表示降价 / 出错 / 危险；深绿只做品牌与主操作 | Sale 标签失去警示力，用户对红色脱敏 |

> **为什么把"乱"翻译成数字**：审美无法验收，刻度可以。**"这个页面有 43 种字号"是能测出来的，"这个页面不好看"没法争论出结果。**所以这套规范全部写成可校验的数值，评审时对着量即可。

### 2.2 字阶（8 级，不多不少）

--t8 · 56px / 1.06Sea glass

--t5 · 20px / 1.3Card title / 价格大字

--t1 · 11px / 1.4导航 / 标签 / 眉标

| 层级 | 字号 | 字族 | 字距 | 用在哪 |
| --- | --- | --- | --- | --- |
| H1 首屏主标题 | 40–56 | 衬线 | -.02em | 仅首屏，全站只有一处 |
| H2 区块标题 | 28 | 衬线 | -0.005em | 各内容区块 |
| H3 卡片标题 | 20 | 衬线 | 0 | 商品名、文章标题 |
| Body 正文 | 14 | 无衬线 | .005em | 全站基准 |
| Nav / Label | 11–12 | 无衬线 | .14em 大写 | 导航、标签、按钮、眉标 |
| 价格 | 14–20 | 无衬线等宽数字 | 0 | 必须开 `tabular-nums`，否则金额列会跳 |

> **为什么是这 8 级而不是更细**：11 与 12 差 1px，在 14px 正文旁边几乎无法分辨，但会让代码里出现"这里到底该用 11 还是 12"的争论。**刻度少一级，团队少一次讨论。**需要区分时用字重、颜色、字距，不用字号。

### 2.3 间距（8px 基数）

--sp1 · 4图标与文字之间

--sp2 · 8标签内边距、紧凑行距

--sp3 · 12表单行间距

--sp4 · 16卡片内边距（小）

--sp5 · 24卡片内边距（标准）

--sp6 · 32区块内元素间距

--sp7 · 48区块之间

--sp8 · 64大区块之间

--sp9 · 88页面首尾留白

规则：**任何 margin / padding 只能取这 9 个值**。设计稿上量出 18px，写 16 而不是 18——这 2px 的差异肉眼不可见，但它会让间距体系失去一致性。

### 2.4 三层容器

**底 · Cream**#FAF6EF 页面背景、区块背景

**面 · Paper**#FFFFFF 卡片、表单、表格、抽屉

**块 · Sea**#1B3A34 页脚、主 CTA、强调条

层次靠这三层的**明度差**建立，不靠阴影。规则：

- 同一屏内不出现同层叠同层（paper 上再放 paper 卡片，边界会消失）。
- 需要第三层时用 `--sand` 或加描边，**不引入第四种底色**。
- 深色块（sea）在一个页面里最多两处，且不能相邻——否则页面重心分裂。

### 2.5 描边、圆角、阴影

| 项 | 值 | 规则 |
| --- | --- | --- |
| 圆角 | 0 / 2px | 全站几乎不用圆角。2px 只用于输入框与标签，卡片与按钮直角。圆角是"软萌"语言，与品牌的"旧物感"冲突 |
| 描边 | 1px `--line` | 所有容器靠描边分界，不靠阴影 |
| 阴影 | `--shadow-s` 0 1px 2px rgba(22,19,15,.05) `--shadow-m` 0 10px 30px rgba(22,19,15,.08) | 只有两类元素用阴影：① 浮层（抽屉、搜索浮层、下拉）用 m；② 极少数需要抬起的卡片用 s。**列表里的卡片一律不加阴影** |
| 分割线 | 1px `--line2`（#F0EAE0） | 比描边更淡，用于同一容器内的行分隔 |

### 2.6 图标

- **线性图标**，1.5px 描边，24×24 视框，圆头端点。
- 尺寸只用两种：页头 17px、内容区 20px。禁止混用 18 / 22 这类中间值。
- 图标必须配文字或 `aria-label`，不单独承担语义（购物袋除外）。
- 图标颜色跟文字走（`currentColor`），不单独设色，避免出现"深绿文字配灰色图标"。

## 3 组件库

### 3.1 按钮（三种，不多不少）

> Primary Ghost Small

| 类型 | 高度 | 内距 | 用在哪 | 规则 |
| --- | --- | --- | --- | --- |
| Primary | 44–46px | 0 26px | 每屏最多一个（加购、结算、Pay） | 深绿实心；hover 加深 8% |
| Ghost | 44–46px | 0 26px | 次级操作（View all、Continue shopping） | 透明底 + 描边；hover 描边变深绿 |
| Small | 36px | 0 18px | 商品卡加购、表格行操作 | 字号 11px；用于密集区域 |

文字规则：全大写 + `.14em` 字距 + 500 字重。**按钮文案不超过 3 个词**，超过改用 Ghost 或缩写成动词。

### 3.2 标签（Badge）

> New Best Seller Sale Only 3 left

规则：① 一张商品卡最多 2 个标签；② 优先级 SALE > LIMITED > NEW；③ Sale 用 clay 实底，其余描边；④ **标签不用阴影**（阴影会让它在图片上"浮起来"，显得廉价）。

### 3.3 表单

> Email address wrong@format

| 状态 | 表现 | 规则 |
| --- | --- | --- |
| 默认 | 1px `--line` 描边，白底，44px 高 | 不自带圆角阴影 |
| 聚焦 | 描边变 `--sea` + `--focus-ring` | 不改变尺寸（避免布局跳动） |
| 错误 | 描边 `--clay`，下方 12px 错误文案 | 提示语必须说"怎么改"，不写"输入有误" |
| 成功 | 描边不变，右侧绿色对勾 | 不整块变绿 |
| 只读/锁定 | 底变 `--cream`，去描边，右侧给 Change 入口 | 用于结算页已登录的邮箱 |

### 3.4 商品卡

> **Foxtrot Pendant**$82.00 $102
>
> Add to bag

- 结构（自上而下）：主图（1:1）→ 悬停换次图 → 标题（14px，单行截断）→ **金属色点行** → 评分（星 + 分 + 条数）→ 价格（现价 + 划线价）→ 加购按钮（Small）。
- 图与文字间距 `--sp3`；标题与色点行间距 2px；色点行与评分为 `--sp1`。
- **色点不压图片。**原来把 `.card__sw` 绝对定位在图片右上角，问题有三：① 挡住商品本身（首饰细节都在中间偏上）；② 和左上角的 BEST SELLER / NEW 角标左右对峙，视觉上变成两个争夺点；③ 圆点直接压在照片的浅色背景上，12px 的金/银两点几乎分不出颜色。现在移到标题下方、图片之外，配一行金属名文字（`Gold / Silver`），**色点负责扫视、文字负责确认**。
- **单色商品不显示色点行。**只有一个点等于没有信息，纯占位；多色才出现。
- **不在卡片上重复显示 SAVE $X**——角标已经说明，价格行的划线价已经说明，第三次重复是噪音。

### 3.8 Cookie 同意条（FR-S-095）

> We use cookies to run the store and, with your permission, to understand how it is used. Learn more
>
> Only necessary Accept all

| 项 | 规则 |
| --- | --- |
| 位置与层级 | 固定底部、通栏，`z-index:80`（低于抽屉 95、高于内容） |
| 动作数 | **只给两个**：Only necessary（幽灵）/ Accept all（cream 实底）。不做"管理偏好"二级弹窗 |
| 桌面 / 移动 | 桌面单行左右分布；≤900px 转上下两行（文案在上、按钮右对齐） |
| **不留白坑** | 条高桌面约 66px、手机约 110px。**写死 `padding-bottom` 必有一端错**：实现改为 JS 实测条高写入 `--ckh`，`body.ck-open{padding-bottom:calc(var(--ckh, 74px) + 14px)}` |
| 状态 | 点击写 `localStorage.tideglass_cookie`（`all` / `essential`），条消失、padding 解除，不需要刷新 |
| 合规 | 条是**归因的前置条件**：未选择前不下发营销像素（FR-S-095 与 7.8 归因模型联动） |

### 3.9 预计送达行（FR-S-167）

> ▭ Order today, arrives **Nov 23 – Nov 29**
>
> 跨度 >21 天（旺季 / 节假日）时退化为：Ships within **1–2 business days**

| 项 | 规则 | 踩过的坑 |
| --- | --- | --- |
| 位置 | 价格与税费行之下、卖点列表之上；左侧 14px 卡车图标 | — |
| 整句出处 | **由 `etaText()` 返回整句**，外层不再拼前缀 | 本轮出过病句：外层写死 `Order today, arrives`，函数在超跨度时返回 `Ships within 2 business days`，拼成 "arrives Ships within…" |
| 日期格式 | `Nov 23 – Nov 29`（月缩写 + 日，跨月也这样写），日期段 sea 色 / 字重 500 | 不要写年份，也不要用 11/23 这种数字格式——欧美站更认月缩写 |
| 退化阈值 | 跨度 >21 天才退化为相对表述 | 原来写 >14，工作日累加后正常单子都会触发（7+12 天算出来就是 14~16 天），等于天天给相对表述 |
| 信息不重复 | 物流信息只在送达行出现一次。卖点固定 **4 条**且互不重叠：保色 / 防水不褪 / 316L 低敏 / 满 $95 免邮（FR-S-052） | ① 原卖点混进一条「7–12 days to the US」，与送达行重复；② 免邮门槛同时出现在税费行和卖点里，说了两遍。税费行现只写 `Duties included` |

### 3.10 筛选条与筛选抽屉（v1.2 重做）

旧版把 9 个筛选条件（All metals / Gold / Silver / All prices / Under $70 / $70–$100 / Over $100 / In stock）全部平铺成一排方块按钮，加排序下拉。三个问题：

- **视觉比商品还响。**9 个等高方块排成一行，形成的色块面积和重量超过第一排商品图，进门先看到一堆按钮而不是首饰。
- **字太小。**为了塞进一行，字号压到 9–10px，手机上更小，属于"能点但不该这么小"。
- **手机上挤成三行。**按钮自动换行后，件数与排序被顶到第三行，筛选条高度接近一屏的 1/6。

> Filter 1 Gold × 9 pieces Sort Featured ▾

| 项 | 规则 | 为什么 |
| --- | --- | --- |
| 入口 | 一个 `Filter` 胶囊（描边版；有选中条件时变实底并带数字角标） | 实底/描边的切换本身就是状态提示，不需要额外说明文字 |
| 已选条件 | 入口右侧逐条显示为可摘除的浅底标签（`Gold ×`），点 × 立即取消该条 | 筛选后最常做的操作是"去掉某一个"，不该让人重开抽屉去找 |
| 件数 | `9 pieces`，右对齐靠近排序 | 文案用 pieces 不用 items——珠宝语境下 pieces 更自然 |
| 排序 | `Sort` 标签 + 圆角下拉，与筛选同为胶囊语言 | 旧版下拉是 2px 圆角的方角框，与整站的圆胶囊语言不一致 |
| 抽屉方向 | 桌面右侧滑出 410px；**≤900px 全屏铺满** | 手机屏宽本来就窄，右侧留一条缝只会让选项文字挤 |
| 抽屉结构 | 标题栏（Filter + 关闭）→ 可滚动的分组区（Metal / Price / Availability）→ 固定底部（Clear all + Show N pieces） | 底部操作固定，滚动选项时不会丢失"确认"入口 |
| 选中标记 | 文字变 sea 色 + 加粗 500 + 右侧一个 6px 圆点 | 不做复选框：单选场景下复选框会让人以为可以多选 |
| 点击后 | 选项是真实链接（`?metal=Gold`），点击即跳转并**自动关闭抽屉** | 抽屉状态必须随路由渲染清掉，否则返回列表时抽屉还开着 |
| Clear all | 左下角文字链接（下划线），回到无参数的本集合 | 与右下角实底按钮形成主次，不会两个按钮互相打架 |

## 4 页面规范

逐页给出「主角 / 层次 / 关键尺寸」，避免每页重新发明一遍。

| 页面 | 主角 | 层次结构 | 关键尺寸 |
| --- | --- | --- | --- |
| 首页 | 首屏大标题 + 轮播图 | 首屏（cream）→ 横滑商品（cream）→ 数字背书（sea 条）→ 题材磁贴 → 故事（cream+图） | 首屏 `min(76vh, 640px)`；H1 `clamp(40px, 4.4vw, 60px)`；区块间距 88px |
| 集合页 | 商品网格 | 页头（cream）→ 筛选条（sticky，两个控件 + 已选标签）→ 网格（cream） | ≥1281 四列 / ≤1280 三列 / ≤620 两列；列距 16px，行距 48px。**筛选条在 ≤900px 变为两列网格**（Filter \| Sort 同行，标签与件数第二行） |

| 结算页 | 右栏订单摘要 | 左：信息 → 支付（分步）；右：摘要（sticky） | 左 59% / 右 41%（`1.18fr .82fr`）；摘要 sticky top 96px |

| 后台 | 数据 | 左侧导航（**238px**，sea 底）+ 顶栏 + 内容区（cream） | 表格行 48px；卡片内距 20px |

## 5 响应式

v1.0 写的是"三档断点"，但代码实际有**五个**转折点。断点表和代码对不上，验收时就没法判断"这是 bug 还是设计"——所以这里按代码实测值重写。

| 宽度 | 导航 | 商品网格 | 首屏 | 结算页 |
| --- | --- | --- | --- | --- |
| ≥ 1281 | 11 项全展示 + mega menu | 4 列 | 左文右图 | 两栏 59/41 |
| 1201–1280 | 11 项全展示 + mega menu | 3 列 | 左文右图 | 两栏 |
| 981–1200 | **收为汉堡** | 3 列 | 左文右图 | 两栏 |
| 901–980 | 汉堡 | 3 列 | **上下堆叠**（图在上） | 两栏 |
| 621–900 | 汉堡 | 3 列 | 堆叠 | **单栏**（摘要置顶） |
| ≤ 620 | 汉堡 | **2 列** | 堆叠 | 单栏 |

> **为什么 980 和 1200 是两个断点，而不是一个。**导航在 1200 就收（因为 11 项 + 间距在 1200 以下会挤到换行），但首屏在 981–1200 仍是两列很好看（文案 44vw 侧栏够宽）。硬并成一个断点，要么 1180 时首屏过早塌成堆叠，要么 1100 时导航挤成两行。**分开设置不是不统一，是两件事的临界点本来就不同。**

三条硬性检查（每次改版都要过）：

三条硬性检查（每次改版都要过）：

1. **任何宽度下不出现横向滚动**（`document.documentElement.scrollWidth <= clientWidth`）。
2. **触控目标 ≥ 44×44px**（加购、关闭、数量步进）。
3. **正文在任何宽度下不小于 14px**——移动端常见错误是把字号压到 12px 塞进更多内容。

## 6 交互与动效

| 场景 | 时长 | 缓动 | 说明 |
| --- | --- | --- | --- |
| hover 变色 | 180ms | ease | 只变颜色，不变尺寸 |
| 抽屉滑出 | 320ms | cubic-bezier(.22,.61,.36,1) | 出快进慢，收尾有停顿感 |
| 状态切换（tab / 手风琴） | 220ms | ease | 高度动画不超过 300ms，否则显得迟钝 |
| 图片淡入 | 400ms | ease-out | 懒加载图淡入，避免"突然出现" |
| Toast | 200ms 进 / 停留 3s | ease | 最多同时 2 条 |

> **动效只用来说明"什么变了"，不用来装饰。**判断标准：把动画去掉，用户是否还能理解发生了什么？如果能，这个动画就不该有。首页英雄图的自动轮播是例外（它承担内容轮换职责），但必须可关。

## 7 无障碍

| 项 | 要求 | 校验方式 |
| --- | --- | --- |
| 对比度 | 正文 ≥ 4.5:1；大字（≥18px 或 14px 粗体）≥ 3:1 | 浏览器取色计算；`--glass` 不可用于正文（对 cream 只有 2.1:1） |
| 键盘 | Tab 可走完全流程（加购 → 结算 → 支付）；焦点始终可见 | 拔掉鼠标走一遍 |
| 焦点样式 | 统一 `outline:2px solid var(--sea); outline-offset:3px` | 不用 `outline:none` |
| 图片 | 装饰图 `alt=""`；商品图 alt 写"商品名 + 视角" | 禁用图片后仍能理解页面 |
| 表单 | 每个输入有 `label` 关联；错误用 `aria-live` 播报 | 屏幕阅读器测试 |
| 动效 | 尊重 `prefers-reduced-motion`，关闭轮播与滑出动画 | 系统开启后检查 |
| 触控 | 点击区 ≥ 44×44px | 移动端逐一点 |

## 8 验收清单

设计交付前逐条打勾。这 12 条全部机械化，不需要审美判断：

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 字号种类 | 全站 ≤ 8 种（`grep -o "font-size:[0-9.]*px" \| sort -u \| wc -l`） |
| 2 | 间距种类 | 全部落在 4/8/12/16/24/32/48/64/88 之内 |
| 3 | 字体族 | 衬线 1 + 无衬线 1，共 2 个 |
| 4 | 底色种类 | cream / paper / sand / sea 四种，不出现第五种 |
| 5 | Clay 用色 | 只出现在 Sale 价、错误、删除三处 |
| 6 | 每屏主角 | 每屏只有一处最大字号 / 深色块 |
| 7 | 横向滚动 | 470 / 900 / 1200 / 1440 四个宽度下 `scrollWidth ≤ clientWidth`；**并定位到具体溢出元素**，不靠 `body{overflow-x:hidden}` 掩盖 |
| 8 | 触控目标 | 移动端所有可点元素 ≥ 44px |
| 9 | 对比度 | 正文 ≥ 4.5:1 |
| 10 | 键盘流程 | Tab 可完成一次加购到支付 |
| 11 | 图片 alt | 所有 `<img>` 有 alt 或明确装饰标记 |
| 12 | 功能回归 | 改样式后 `e2e.js` 与 `e2e-flow.js` 全绿（样式改动不得影响交互） |
| 13 | 悬浮面板不裁切 | mega menu 悬停展开后完整可见（父级 `overflow` 不能是 `hidden`） |
| 14 | 固定条不遮内容 | Cookie 条显示时页脚最后一行仍可滚到（`body` 的 `padding-bottom` ≥ 条实际高度） |
| 15 | 导航有当前位置 | 进入任一集合页后，对应导航项必须有 sea 色 + 下划线，且带 `aria-current="page"` |
| 16 | 筛选可撤销 | 已选条件必须以可点击的标签形式露出，点一次即取消；抽屉内选中项唯一（同一分组不能两项同时高亮） |

> **第 12 条最重要**。上一轮改 UI 时就出现过一次：样式调整把某个类名改了，结算步骤条被撑成 151px 高、文案居中错位，而功能测试照样全绿——因为测试只检查元素存在，不检查布局。**所以样式改动的验收必须包含"功能回归 + 逐页视觉复核"两件事，缺一不可。**

### 9.5 第二轮观感问题（v1.2，6 项已修）

这一轮的输入不是"有没有功能"，而是"看起来对不对"。五个问题全部来自真实观感，验收清单测不出来，只能靠眼睛。

| # | 问题 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | 移动端与桌面端"像两个网站" | 三处叠加：① 筛选条在手机上挤成三行方块按钮（桌面一行）；② Cookie 条压住商品与页脚；③ 字标 24px/.3em 在 470px 下顶到汉堡按钮 | 筛选条改两列网格（Filter \| Sort 同行）、Cookie 条按实测高度留白、移动端字标降到 20px/.22em。**两端现在是同一套设计语言的不同排布** |
| 2 | 点 Best Sellers 后"没有变化" | 页面标题与商品都换了，但导航项**没有任何选中态**，视觉上像"点了没跳" | 导航项按当前集合加 `is-active`（sea 色 + 下划线）与 `aria-current="page"` |
| 3 | 色点压在商品图上、与图片内容重叠 | 色点绝对定位在图片右上角，与左上角角标对峙，且深色/浅色图上看不清 | 移到标题下方，配金属名文字；单色商品不显示 |
| 4 | 筛选按钮"太难看了" | 9 个方块按钮平铺，字号 9–10px，视觉重量超过商品 | 改 Filter 胶囊 + 已选标签 + 圆角 Sort 下拉 + 右侧分组抽屉（见 3.10） |
| 5 | Logo"太生硬" | 21px/.18em 全大写衬线，九字母等距，像打字机编号 | Italiana 24px/.30em + 22px 海玻璃符号（见 3.11 与品牌方案 v2.1） |
| 6 | 原型调试浮层（右下角圆球）压在 Cookie 条按钮与正文上 | 固定定位 + `z-index:300`，高于抽屉（95）与 Cookie 条（80） | 桌面版随 Cookie 条上浮、抽屉打开时让位到左侧并压淡到 0.32；**≤700px 直接隐藏** |

> **这一轮的方法论：先量后改。**五个问题里有三个的根因和直觉不一样——① "移动端不一样"不是布局没做响应式，而是筛选条与 Cookie 条把内容挤走了；③ 色点不是"位置不好"而是"放错了容器"；⑤ "生硬"不是字体不够花，而是字距不够宽导致九个字母各自为政。**凭直觉改会改错方向**（比如把字标换成手写体会更糟，见品牌方案 v2.1 的说明）。
