两套可运行的东西，**前后端完全独立**，通过 REST 通信：

| 服务 | 目录 | 端口 | 说明 |
|---|---|---|---|
| API + 静态托管 | `app/server` | 4600 | Node 原生 http，零第三方依赖 |

### 硬约束（已写进代码，不是文档承诺）

- 价格只在服务端算，前端传上来的金额字段一律丢弃
- 下单必须带 `quoteId`（15 分钟有效），金额不一致直接 `PRICE_CHANGED`
- 库存只走流水，`stockLedger` 只追加不修改，判据是「末条 balanceAfter = 当前库存」
- 订单状态机单向，终态不可回退，退款必须走 `/refund` 出口（回补库存 + 释放券 + 冲减消费）
- 后台改任何东西，前台下一次请求就变 —— 同一份 JSON，没有第二份数据源

## 七、文档维护规则

- **HTML 是源，MD 是产物**：`review/*.html` 是手写源文件，`handover/` 里的对应 MD 由 `node tools/html2md.js` 生成。改内容请改 HTML 再重新生成，直接改 MD 会在下次生成时被覆盖。
- **接口文档要跟代码对账**：`node tools/gen-openapi.js` 从路由实现重新生成 `openapi.json`，改接口后必须跑一次，否则文档会悄悄过期。
- **截图会过期**：改 UI 后跑 `node tools/shot-doc.js <输出目录> [--only=admin|store] [--w=宽度]` 重出，别手工截。
- **版本号规则**：改需求 → FRD 进位；改技术方案或数据模型 → SDD 进位；只改文案 → 不动版本号，改「最后更新」日期。
