### 代码

| 服务 | 目录 | 端口 | 说明 |
|---|---|---|---|

node app/server/seed.js            # 生成演示数据（36 款商品 / 67 个变体 / 90 单 / 200 条库存流水）

### 硬约束（已写进代码，不是文档承诺）

- 价格只在服务端算，前端传上来的金额字段一律丢弃
- 下单必须带 `quoteId`（15 分钟有效），金额不一致直接 `PRICE_CHANGED`
- 库存只走流水，`stockLedger` 只追加不修改，判据是「末条 balanceAfter = 当前库存」
- 订单状态机单向，终态不可回退，退款必须走 `/refund` 出口（回补库存 + 释放券 + 冲减消费）
- 后台改任何东西，前台下一次请求就变 —— 同一份 JSON，没有第二份数据源

## 六、还缺什么（卡在你这边）

完整清单见 `01-产品需求/FRD-功能需求说明书-v2.10.md` 第 13 节（16 项，分 🔴 阻断营业 / 🟡 影响体验 / 🟢 决策项）。这里只列**不开门就不能收钱**的 5 件：

| 资料 / 决定 | 用途 | 没有它会怎样 |
|---|---|---|
| **PayPal Live 密钥** | 收款 | 停在沙盒，钱不会真到账。沙盒验完后换密钥即可，**建议直填服务器，不要经聊天发送** |
| **Resend API Key + 域名 SPF/DKIM** | 订单确认 / 发货 / 退款信 | 全站邮件 dry-run，只打日志不发信。客户下了单收不到任何确认 |
| **美国各州销售税方案** | 合规 | **当前完全未收销售税**。原设计靠 Stripe Tax，本站未接 Stripe，PayPal 不做税务计算。超过各州 nexus 门槛不申报会累积罚金 |
| **面单由谁打** | 发货 | 后台只存单号、不生成面单。海外仓代打只需给单号；自己打要另接 EasyPost / Shippo |
| **清理线上测试数据** | 上线 | 98 笔订单 / 60 余条评价（2026-11-15 实测，仍在增长） / 沙盒待付款单都在生产库。**假评价是 FTC 明文禁止的行为**，上线前必须清 |

## 八、文档维护规则

- **HTML 是源，MD 是产物**：`review/*.html` 是手写源文件，`handover/` 里的对应 MD 由 `node tools/html2md.js` 生成。改内容请改 HTML 再重新生成，直接改 MD 会在下次生成时被覆盖。
- **接口文档要跟代码对账**：`node tools/gen-openapi.js` 从路由实现重新生成 `openapi.json`，改接口后必须跑一次，否则文档会悄悄过期。
- **截图会过期**：改 UI 后跑 `node tools/shot-doc.js <输出目录> [--only=admin|store] [--w=宽度]` 重出，别手工截。
- **版本号规则**：改需求 → FRD 进位；改技术方案或数据模型 → SDD 进位；只改文案 → 不动版本号，改「最后更新」日期。
- **品牌沿革，历史文档不追溯**：项目换过三次名 —— `SEREIA` → `Wildkind` → `TIDEGLASS` → **`LASTGROVE`**（2026-11-15 定稿，`LASTGROVE` 之前还有一版 `Weftvale` 候选，已撤回）。**当前有效文档、代码、数据、域名、邮件、券码一律是 LASTGROVE**；被取代的历史版本文档（API v1.2–v1.5、SDD v2.3–v2.6、FRD v2.5–v2.9、部署手册 v1.2 及更早、各期测试报告与验收报告、品牌命名各案）**保持原文不改** —— 改了就看不出「当时是什么样」，版本留档就失去意义。读这些文档时把 `TIDEGLASS` 直接理解成 `LASTGROVE` 即可。
  文档编号 `TG-*` 同样保留历史值（如 `TG-BR-003`、`TG-OPS-001`），新增文档改用 `LG-*`。
