## 1 PayPal 换 Live 密钥（P-02）

**为什么只有你能做**：需要登录你的 PayPal 商家账号走应用审核，密钥属于账户凭据。

### 步骤

1. 登录 <https://developer.paypal.com/dashboard/applications>，确认当前是 **Live** 而不是 Sandbox（页面左上角有切换开关）。
2. 如果还没有 Live 应用：`Apps & Credentials` → `Live` → `Create App`，名字填 `Lastgrove Store`，类型选 `Merchant`。
3. 创建后拿到两个值：**Client ID** 和 **Secret**（Secret 要点击 `Show` 才显示，只显示一次）。
4. 到服务器上改环境变量（Coolify 里 `Environment Variables`，或服务器上的 `.env`）：

```
PAYPAL_ENV=live
PAYPAL_CLIENT_ID=<Live 的 Client ID>
PAYPAL_CLIENT_SECRET=<Live 的 Secret>
PAYPAL_WEBHOOK_ID=<Live 应用的 Webhook ID>
```

5. Webhook 地址填：`https://lastgrove.com/api/v1/payments/webhook/paypal`，勾选事件 `PAYMENT.CAPTURE.COMPLETED`、`PAYMENT.CAPTURE.REFUNDED`、`CHECKOUT.ORDER.APPROVED`。
6. 保存后重启服务。

### 三件必须注意的事

- **不要把这些值发到聊天里**。前面服务器 root 密码和 PayPal 密码都出现过在聊天记录中，这两个密码请顺手改掉，并开 PayPal 两步验证。
- Live 密钥配错的现象是「付款页一直转圈」而不是报错，所以改完先用 $1 的自测商品走一遍真实付款，再退给自己。
- 沙盒那两笔单（`#TG1133` / `#TG1134`）不要带到线上，清库工具会一并清掉。

### 改完怎么验

改完告诉我，我跑一条命令就能确认：`GET /api/v1/payments/methods` 返回的 `mode` 应该是 `live` 而不是 `sandbox`。这一步我不会替你做，因为需要你先把值填进去。

## 2 Resend 建 Key + 验证域名（P-03）

**为什么只有你能做**：需要登录你的 Resend 账号和 Cloudflare DNS。

### 步骤

1. 注册 / 登录 <https://resend.com>，进 `API Keys` → `Create API Key`。
   - 权限选 **Sending access**（不要选 Full access，发信不需要那么大的权限）。
   - 域名选 `lastgrove.com`。
2. 进 `Domains` → `Add Domain`，填 `lastgrove.com`，区域选 `us-east-1`。
3. Resend 会给出 3 条 DNS 记录，到 Cloudflare 的 DNS 页面逐条添加：

| 类型 | 名称 | 关键点 |
| --- | --- | --- |
| TXT | `resend._domainkey` | DKIM，值很长，整段复制 |
| TXT | `send` | SPF，值为 `v=spf1 include:amazonses.com ~all` |
| MX | `send` | 优先级 `10`，值 `feedback-smtp.us-east-1.amazonses.com` |

4. **三条记录都必须把橙色云朵点成灰色（DNS only）**。这一步最容易错：开了代理（橙云）后 DNS 查询被 Cloudflare 接管，Resend 永远验不过，而页面上只会显示「Pending」不告诉你为什么。
5. 回 Resend 点 `Verify DNS Records`，通常 5~30 分钟变绿。
6. 把 Key 填进服务器：

```
RESEND_API_KEY=re_xxxxxxxx
MAIL_FROM=orders@lastgrove.com
MAIL_REPLY_TO=hello@lastgrove.com
```

### 现状说明

邮件代码已经写完并且**未配密钥时会走 dry-run**——不是不发，而是把整封信打到日志里，内容、金额、税行都能核对。所以你现在想先看信长什么样，我可以直接从日志里取给你。

配好之后会真的发出三类信：订单确认、已发货（带轨迹链接）、已退款。

### 改完怎么验

告诉我，我下一单真实订单，然后在 Resend 的 `Emails` 页面能看到投递记录、`Delivered` 状态。如果显示 `Bounced`，多半是 `MAIL_FROM` 的域名和验证的域名不一致。

## 3 问海外仓：面单谁打（P-04）

**为什么只有你能做**：这是你和海外仓之间的商务约定，代码不知道答案。

### 只需要问一句

> 我们出单后，你们是**代打面单**（我们只给订单信息，你们贴好发走），还是**我们自己打面单**再给你们 PDF？

### 两种答案对应两套做法

| 海外仓的答复 | 我们要做的 | 工作量 |
| --- | --- | --- |
| 他们代打 | 不用改代码。现在后台就是「填单号 → 自动订阅轨迹 → 发发货信」 | 0 |
| 我们自己打 | 要接 EasyPost 或 Shippo，在后台加「生成面单」按钮，出 PDF + 自动回填单号 | 约 1.5 天 |

**建议**：如果是代打，就直接用现在的流程，别为了"看起来自动化"去接物流 API——多一个第三方就多一个故障点和一份月费。

## 4 买 17TRACK 套餐（P-07）

**为什么只有你能做**：要付钱。

### 背景

17TRACK 免费额度下 **USPS 的轨迹会被政策拦截**，返回错误码 `-18019823`；UPS / FedEx 正常。现在的降级处理是：查不到轨迹时，前台给一个「去承运商官网查」的按钮，用户点过去自己看。这不是 bug，是额度限制。

### 步骤

1. 登录 <https://www.17track.net/> 的账号（就是现在配在服务器上的那个）。
2. 买 **¥299 / 万单** 的套餐（按当前发货量够用一年以上）。
3. 回后台 `Tracking` 页面（或 `POST /admin/orders/:n/tracking/refresh`）点一次刷新，把之前订阅失败的单号补订。

**不用改任何代码**，也不用重启服务。

## 5 工商经营范围变更（P-15）

**为什么只有你能做**：需要你的营业执照与法人身份。

### 要加的经营范围

- 珠宝首饰零售
- 珠宝首饰批发
- 互联网销售（除销售需要许可的商品）
- 货物进出口

### 为什么不做不行

1. **支付通道合规审查**会核对经营范围和实际售卖品类。卖珠宝但经营范围里没有珠宝，审核大概率驳回，或者过了之后被风控冻结。
2. **发票开具**：经营范围决定你能开什么品目的发票。
3. 进出口这一项决定了后续能不能自己报关，而不是永远依赖海外仓。

### 怎么办

- 线上：当地政务服务网 / 一网通办，找「经营范围变更」，1~3 个工作日出结果。
- 线下：市场监管局窗口，带营业执照正副本、法人身份证、公章。
- 变更完记得同步更新**支付通道、银行对公账户、海外仓合同**上的主体信息。

## 6 各州销售税注册与税号（P-01 的剩余部分）

**代码这边已经做完了**，这条只剩「你要去哪几个州注册、税号是多少」这个纯商业 + 法务问题。

### 现在的机制（重要，决定你什么时候必须动手）

美国销售税是按**收货州**收的，但只有在某州达到 **economic nexus** 门槛后才有代收义务。各州门槛不同，常见的是：

| 州 | 门槛（2026 口径，报税前请复核） |
| --- | --- |
| California | 年销售额 $500,000 |
| New York | 年销售额 $500,000 且 100 笔交易 |
| Texas | 年销售额 $500,000 |
| 多数中小州 | $100,000 或 200 笔交易 |

所以首月的正确动作是：**一个州都不注册，后台一个税率都不填**。系统此时对所有州收 $0 税——这是对的，不是漏了。

### 什么时候开始配

1. 每月导一次 `GET /admin/export/tax.csv`（现在没配税率，导出会是空的，但有订单量）。
2. 盯住**单州累计销售额**。任一州逼近门槛的 70%，就在那个州注册。
3. 注册拿到税号后，后台 `Settings → Sales tax` 填上：一行一州，格式 `California: 7.25`。填完**立刻生效**，下一单就开始收。

### 三件事别做错

- **别一次性把所有州都填上**。没注册就收税 = 收了钱不交出去，这比不收严重得多。
- **别用"取两位字母"的方式判断州**。`New York` 取前两位是 `NE`（Nebraska），会收错州。代码里已经是精确匹配 + 全名归一，你只要正常填州名就行。
- **历史订单的税率是锁定的**。后台改税率不会改变已成交订单上的税额，否则报税时数字对不上。

### 一句实务建议

首年别自己申报。注册 1~2 个州之后，用 TaxJar / Avalara 这类服务（约 $19~$50/月起）代报，比你自己研究每个州的表格便宜——**报错一次罚的钱够付三年服务费**。

## 7 商品实拍图（P-16）

**为什么只有你能做**：需要实物和拍摄。

### 现状

现在商品图是渲染图，风格统一、干净，但**转化率会明显低于实拍**。参考站（Atolea、Pura Vida）的图都是真人佩戴实拍，这是珠宝类目最硬的转化因素——用户买的是「戴在我身上什么样」，不是「这个东西长什么样」。

### 最小可行的做法

不用一次拍 100 款。先拍 **8~12 款主推**，每款 3 张：

1. 白底正面图（当主图，和现有渲染图风格一致）
2. 真人佩戴图（脖子 / 手腕 / 手指特写，自然光，不要棚拍白光）
3. 细节图（扣头、链节、石头，证明做工）

### 要求

- 正方形，至少 1600×1600，JPG
- 不要加滤镜、不要美颜皮肤、不要 P 掉产品
- 文件名用 SKU：`LG-101-gold-01.jpg`
- 交给我之后我跑 `tools/opt-img.js` 批量压成 WebP，前台自动用新图

### 一个提醒

如果供应商能提供实拍，优先用他们的——但**必须要求他们证明图是他们自己拍的**。珠宝类目盗图投诉很多，用了别人的图，下架是小，被索赔是大。
