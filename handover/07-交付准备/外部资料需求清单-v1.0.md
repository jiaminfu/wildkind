## 0 先说结论

代码侧现在的状态是：**业务流程全部跑通、账目自洽、后台可管，但支付是模拟的、邮件没发、物流靠手填。**

要变成"能真的收钱发货"，还差 **6 类外部资料**。其中 **3 类会直接卡住上线**（标 🔴），3 类可以在上线后补（标 🟡）。

| 阻塞级别 | 含义 |
| --- | --- |
| 🔴 上线前必须有 | 缺了就无法真实收款 / 无法发货 / 网站打不开 |
| 🟡 可以先上线再补 | 不影响成交，但会影响体验或运营效率 |
| 🟢 长期完善 | 有余力再做 |

**最短路径**：先把 🔴 的 6 项（Stripe 密钥、域名、收货主体信息、物流账号、发件邮箱、商品实拍）拿到，就能上线收第一单。

## 1 🔴 支付：Stripe

### 1.1 需要你提供什么

| # | 资料 | 从哪拿 | 格式要求 | 用途 |
| --- | --- | --- | --- | --- |
| 1 | **Secret Key**（`sk_live_…` 或测试用 `sk_test_…`） | Stripe Dashboard → Developers → API keys | 字符串，直接贴给我 | 服务端创建支付会话、查询支付结果、发起退款 |
| 2 | **Publishable Key**（`pk_live_…`） | 同上 | 字符串 | 前端挂 Embedded Checkout |
| 3 | **Webhook Signing Secret**（`whsec_…`） | Dashboard → Developers → Webhooks → 添加端点后生成 | 字符串 | 校验支付回调真伪。**这个最重要**，没有它就无法确认"钱真的到账了" |
| 4 | **Webhook 端点 URL** | 由你定（如 `https://tideglassjewelry.com/api/v1/webhooks/stripe`） | 需先有域名 | 接收 `payment_intent.succeeded` / `charge.refunded` 等事件 |
| 5 | **账户所在国家 / 结算币种 / 支持的支付方式** | Dashboard → Settings | 文字说明 | 决定是否开 Apple Pay / Google Pay / Klarna |
| 6 | **Apple Pay 域名验证文件** | Dashboard → Settings → Payment methods → Apple Pay | 文件路径或内容 | 在 Safari 上显示 Apple Pay 按钮 |

### 1.2 我这边会怎么用

```
下单 → 服务端用 sk 创建 PaymentIntent（带 quoteId 算出的金额）
     → 前端用 pk 渲染 Embedded Checkout
     → 用户付款 → Stripe 回调 webhook
     → 服务端验签 → 订单状态 paid → 发确认邮件
```

### 1.3 注意事项

- **不要**把 `sk_live_` 密钥贴到聊天里长期留存。建议放到服务器环境变量，或先用 `sk_test_` 把流程验完，上线当天再换。
- 现在代码里 `payment.mode = "simulated"`，是明确的占位标记——**不会假装成功**，后台订单详情会显示 `simulated`，方便你区分测试单与真实单。
- 部分退款（多件订单只退一件）已在接口层支持（`POST /admin/orders/:number/refund` 带 `amount`），但需要在 Stripe 侧确认你的账户支持部分退款。
- 若暂时不接 Stripe，可以先用 **PayPal / 微信支付 / 银行转账**兜底，但需要告诉我走哪条，接口要改。

## 2 🔴 域名与部署

| # | 资料 | 说明 | 为什么是 🔴 |
| --- | --- | --- | --- |
| 1 | **主域名** | 建议 `tideglassjewelry.com`（品牌名核查报告里有候选） | 没有域名就没有 HTTPS，Stripe 也不给真实收款 |
| 2 | **域名注册商账号权限**（或 DNS 托管商） | Cloudflare / 阿里云 / Namecheap 均可 | 要加 A 记录、CNAME、TXT（邮件验证用） |
| 3 | **服务器 / 托管环境** | VPS（2C4G 起）或 Coolify 实例 | 代码要跑在能公网访问的地方 |
| 4 | **SSH 登录方式** | 密钥或密码 | 部署与排错 |
| 5 | **SSL 证书** | 一般由 Cloudflare 或 Let's Encrypt 自动签发 | 无 HTTPS 则支付被浏览器拦截 |

> **顺序建议**：先买域名 → 解析到服务器 → 跑起来 → 再去 Stripe 配 webhook。反过来做会反复改回调地址。

## 3 🔴 物流与履约

| # | 资料 | 从哪拿 | 用途 |
| --- | --- | --- | --- |
| 1 | **海外仓 / 3PL 的 API 凭证** | 服务商后台或客户经理 | 推单、查库存、拿运单号 |
| 2 | **API 文档或对接说明** | 同上（PDF / 在线文档链接都行） | 我需要知道字段与鉴权方式 |
| 3 | **承运商账号**（USPS / UPS / FedEx / DHL） | 各承运商官网注册，或通过 3PL 的折扣账号 | 生成面单、查轨迹 |
| 4 | **发货时效承诺** | 你定（如 1–2 个工作日处理 + 3–5 天送达） | 前台商品页显示的送达日期靠这个算 |
| 5 | **运费价目表** | 你定或服务商给 | 现在代码里是美国境内 Standard $6.9 / Express $19.9、满 $95 免邮，**这些是我按行业惯例填的占位值**，需要你确认或替换 |
| 6 | **可配送国家与限制** | 目前代码限定 美国 / 加拿大 / 英国 | 若要扩，告诉我 |

### 3.1 如果暂时没有 3PL API

完全可以先上线。当前做法是：**后台「订单详情 → Add tracking」手工填运单号**，订单自动从 `paid` 推进到 `fulfilled`，客户用「单号 + 邮箱」能查到状态与运单号。

代价是每单要手工操作 30 秒左右。**日单量 20 单以内可以接受**，超过就该对接 API 了。

## 4 🔴 邮件发送

| # | 资料 | 从哪拿 | 用途 |
| --- | --- | --- | --- |
| 1 | **发件域名** | 你定（如 `mail.tideglassjewelry.com`） | 发件人地址，影响送达率 |
| 2 | **DNS 记录配置权限** | 同域名管理 | 加 SPF / DKIM / DMARC 三条记录，否则邮件进垃圾箱 |

### 4.1 需要发的 5 类邮件（模板已在 SDD 15.1 定义）

| 邮件 | 触发时机 | 优先级 |
| --- | --- | --- |
| 订单确认 | 支付成功 | 🔴 必须 |
| 发货通知（含运单号） | 后台填运单号 | 🔴 必须 |
| 退款通知 | 退款完成 | 🔴 必须 |
| 评价邀请 | 签收后 7 天 | 🟡 影响复购 |
| 到货提醒 | 缺货商品补货 | 🟢 锦上添花 |

## 5 🔴 经营主体与合规信息

这些会印在网站页脚、发票、退换政策里，**法律上必须真实**。

| # | 资料 | 用途 | 备注 |
| --- | --- | --- | --- |
| 1 | **公司/个体户全称** | 页脚、条款页、发票 | 与营业执照一致 |
| 2 | **注册地址** | 条款页、退换货寄回地址 | 可填办公地址 |
| 3 | **营业执照或注册编号** | 部分支付渠道与平台要求 | Stripe 开户已用则可跳过 |
| 4 | **客服邮箱** | 页脚、邮件回复地址 | 建议 `hello@` 或 `support@` |
| 5 | **客服电话**（可选） | 页脚 | 北美客户偏好有电话 |
| 6 | **退货收件地址** | 退换政策页 | 退货运费归属已在 BR-11 定义 |
| 7 | **EIN / 税号**（美国）或 **VAT 号**（英国） | 发票、IOSS 申报 | 若走 IOSS，需要 IOSS 号 |
| 8 | **隐私政策 / 条款 / 退换政策文本** | 三个页面 | **我可以起草**，但需你确认后由你署名 |

> 合规口径已在 FRD 里定为：GDPR（欧盟客户）+ CCPA（加州）+ IOSS（欧盟进口 VAT）。若首版只做美加英，GDPR 部分可以先上"Cookie 同意 + 数据删除申请入口"这两项最低要求。
