## 1 Resend 是什么，Key 怎么建（P-03）

### 1.1 它到底是什么

你的站要给客户发三封信：**下单确认、发货通知（带轨迹链接）、退款通知**。

发信有两条路：

| 路径 | 结果 |
| --- | --- |
| 直接从自己的服务器发 | 几乎必然进垃圾箱。新服务器没有发信信誉，Gmail / Outlook 会直接判为垃圾邮件，严重时把整个 IP 拉黑，连正常业务邮件都发不出去 |
| 交给专业发信服务 | 信能进收件箱，而且服务商会帮你做身份认证，让 Gmail 相信「这封真是 lastgrove.com 发的」 |

**Resend 就是第二种。** 一句话类比：**它是邮局**。你的网站把信交给它，它负责投递、盖戳、留下投递记录。你只需要给它一个 API Key（相当于开户凭证）。

它同时解决一件你可能没意识到的事：**身份认证（SPF / DKIM）**。没有这个，你发出去的信号称 from lastgrove.com，收件方无法验证，直接进垃圾箱。Resend 会把要配的 DNS 记录列给你，你复制粘贴到域名后台即可。

**免费额度够不够？** 免费版：**3,000 封/月、100 封/天**。我们一单大约 3 封信（确认、发货、可能的退款），也就是**每天 30 单、每月 1,000 单以内完全免费**。超了才 $20/月。你现在不需要付钱。

### 1.2 怎么建 Key（照着点）

**第一步：注册**

打开 <https://resend.com> → `Sign up`。用你的常用邮箱，不需要信用卡。

**第二步：先加域名（不要先建 Key）**

顺序很重要：**先验域名，再建 Key**。反过来的话，Key 建出来也没有可用域名，第一次发信会直接失败，而且报错很难懂。

进 `Domains` → `Add Domain`：
- Domain 填 `lastgrove.com`
- Region 选 `us-east-1`（美国客户为主，选美东）
- 点 `Add`

**第三步：把 3 条 DNS 记录加到 Cloudflare**

Resend 会列出几条记录，长这样（以你页面上实际显示的为准）：

| 类型 | 名称 | 内容 | 说明 |
| --- | --- | --- | --- |
| TXT | `resend._domainkey` | `p=MIGfMA0GCS...`（很长，整段复制） | DKIM 签名，证明信真是你发的 |
| TXT | `send` | `v=spf1 include:amazonses.com ~all` | SPF，声明哪些服务器有权代你发信 |
| MX | `send` | `feedback-smtp.us-east-1.amazonses.com`（优先级 10） | 退信回收，知道哪些地址失效 |

到 Cloudflare → 选 `lastgrove.com` → `DNS` → `Records` → `Add record`，逐条加。

> **最容易错的一步：三条记录都必须点成灰色云朵（DNS only）。**
> 默认是橙色（Proxied）。开了橙云，DNS 查询被 Cloudflare 接管，Resend 永远验不过，而页面上只会显示 `Pending`，**不会告诉你原因**。你会以为是自己配错了，反复折腾。
> 保存前看一眼云朵图标：**灰色**才对。

**第四步：验证**

回 Resend 点 `Verify DNS Records`。通常 5~30 分钟变绿。超过 1 小时还是 Pending，先检查云朵颜色。

**第五步：建 Key**

`API Keys` → `Create API Key`：
- Name：`lastgrove-prod`
- Permission：选 **Sending access**（不要 Full access —— 发信不需要删除域名的权限）
- Domain：选 `lastgrove.com`

**Key 只显示一次**，形如 `re_xxxxxxxx`。复制到密码管理器。

**第六步：填进服务器**

在 Coolify 的环境变量里加（或服务器 `.env`）：

```
RESEND_API_KEY=re_xxxxxxxx
MAIL_FROM=orders@lastgrove.com
MAIL_REPLY_TO=hello@lastgrove.com
```

`MAIL_FROM` 的域名必须是**已经验过的那个**。填了别的域名，Resend 会拒绝发送，错误是 `Domain not verified`。

保存后重启服务。

### 1.3 现在不配会怎样

邮件代码早就写完了，**没配 Key 时走 dry-run**：不是不发，而是把整封信（含金额、税额、税州、折扣、地址）完整打到日志里。

所以：
- **不影响你测试下单流程**——金额对不上、税算错、地址拼接错，全都能在日志里看出来
- **影响的是客户**——收不到确认信。客户下完单没有任何凭证，会来问你「我下单成功了吗」

这就是它排在第一位的原因：**它不是技术问题，是客户体验的第一道缺口**。

### 1.4 配完怎么验

告诉我，我下一单真实订单，然后你在 Resend 的 `Emails` 页面能看到投递记录和 `Delivered` 状态。

如果显示 `Bounced`，八成是 `MAIL_FROM` 的域名和验过的域名不一致。如果 `Delivered` 了但客户说收不到，让对方查垃圾箱——新域名头几天有信誉建立期，这是正常的。

## 3 PayPal：先沙盒，上线前换 Live（P-02）

### 3.1 你的决定带来了什么

沙盒环境可以**完整跑通**：建单 → 跳转 → 批准 → 捕获 → webhook 兜底 → 退款。所有金额、状态流转、幂等、异常分支都能验，**不用改一行代码**。

差别只有一个：**钱不进你的账户**。沙盒里那些「付款成功」是假的。

所以「上线」这个动作本身，就包含「把沙盒密钥换成 Live 密钥」这一步。它不是上线后的补丁，是上线的一部分。

### 3.2 沙盒阶段你能做的验证（不用等我）

在后台下一单，走到付款页，用 PayPal 的沙盒买家账号付款。沙盒账号在 <https://developer.paypal.com/dashboard/accounts> 里能看到（`Sandbox` → `Accounts`）。

付款完成后应该发生：订单变 `paid`、库存扣减、确认信打到日志、后台能看到这笔单。

### 3.3 上线前换 Live 的步骤

1. <https://developer.paypal.com/dashboard/applications> → 左上角切到 **Live**
2. `Create App`，名字 `Lastgrove Store`，类型 `Merchant`
3. 拿 **Client ID** 和 **Secret**（Secret 点 `Show`，只显示一次）
4. 服务器环境变量改成：

```
PAYPAL_ENV=live
PAYPAL_CLIENT_ID=<Live Client ID>
PAYPAL_CLIENT_SECRET=<Live Secret>
PAYPAL_WEBHOOK_ID=<Live 应用的 Webhook ID>
```

5. Webhook 地址填 `https://lastgrove.com/api/v1/payments/webhook/paypal`，勾选：
   - `PAYMENT.CAPTURE.COMPLETED`
   - `PAYMENT.CAPTURE.REFUNDED`
   - `CHECKOUT.ORDER.APPROVED`

6. 重启服务，然后**用 $1 自测单走一遍真实付款，再退给自己**

### 3.4 一个坑，提前说

Live 密钥配错的现象**不是报错，是付款页一直转圈**——前端拿不到 client token，按钮永远不出现，日志里只有一行不起眼的失败。所以改完必须真付一次。

另外沙盒那几笔测试单不要带到线上，清库工具会一并清掉（`node tools/clean-test-data.js --apply`）。

### 3.5 怎么确认切换成功

改完告诉我，我跑一条命令：`GET /api/v1/payments/methods` 返回的 `mode` 应该是 `live`，不是 `sandbox`。

## 4 17TRACK：用免费额度（P-07）

### 4.1 免费额度到底是多少（官方原文口径）

| 项目 | 数值 |
| --- | --- |
| 每月免费额度 | **100 个**（subscription quota） |
| 重置规则 | 每月 1 号重置为 100，**月底清零、不累积** |
| 什么扣额度 | **只有首次订阅（register）扣 1 个** |
| 什么不扣 | 订阅成功后的所有查询、刷新、webhook 推送、自动追踪，**全部不扣** |

这意味着：**一次订阅，终身免费查**。100 个额度 = 100 个包裹的自动追踪，与实际查询频次无关。你天天点刷新也不会多花一个。

### 4.2 我按你的决定做了两处代码改动

**① 注册时不再传 `lang`（省一半额度）**

官方计费规则原文：*"Specifying a translation language during registration will deduct 1 additional quota... (total of 2 quotas: registration + translation)"*。

也就是说，注册时指定翻译语言，会为「成功的翻译」多扣 1 个额度 —— **100 个额度变成 50 单**。

我们只发美 / 加 / 英，USPS、UPS、FedEx 的轨迹本来就是英文。传 `lang:'en'` 等于**花钱把英文翻成英文**。已经删掉，额度从 50 单回到 100 单。

**② 额度用完不再被误判成「单号无效」**

原来额度耗尽（`-18019908`）会走通用的失败分支，在订单上记成「订阅失败」。运营看到会去**催客户重报单号**——而真正该做的是等下月 1 号重置或买套餐。

现在额度类错误（`-18019908` 额度用完 / `-18019907` 撞当日上限）单独识别，订单上写的是「本月自动追踪额度已用完，1 号恢复；期间可直接在承运商官网查」。

**关键是：额度用完不阻断发货。** 保存运单号、发发货信、订单转 `fulfilled` 全部照常，只是没有自动轨迹。这条我专门验过。

### 4.3 后台现在能看见额度

设置页新增 `Tracking quota` 面板：本月剩余 / 已用 / 总量 + 进度条。剩余 ≤ 20 时变红并提示。

之前这个接口存在但前端没接——**额度会在月中悄悄用完，等发货时发现「怎么没轨迹了」就晚了一批单**。

### 4.4 什么时候必须买

| 信号 | 动作 |
| --- | --- |
| 某月发货 **接近 100 单** | 面板变红时就是这个信号，别等撞墙 |
| 用户开始问「为什么查不到轨迹」 | 同上 |
| 旺季（11~12 月） | 提前买，额度**不累积**，上月的用不完不能挪到这个月 |

套餐价 ¥299 / 万单 = ¥0.03/单，按 100 单/月算够用 8 年。**但买的时候不用改代码，把 Key 配好就生效**。

**我的建议**：不用提前买。等面板变红（剩余 ≤ 20）再买。理由：免费额度够你跑完整个验证期，而买早了没用上的额度按 12 个月有效期算，是纯浪费。

## 6 工商经营范围变更：暂缓（P-15）

按你的决定暂不变更。我把风险窗口说清楚，你自己判断什么时候动：

| 阶段 | 工商范围的影响 |
| --- | --- |
| 现在（PayPal 沙盒 + 开发测试） | **零影响**。沙盒不涉及真实资金与合规审查 |
| 换 Live 后小额真实收款 | 通常无感，PayPal 的开户审核已经在店铺注册时做过 |
| 月流水稳定、要开票 / 要对公结算 / 要报关 | **开始有影响**。经营范围决定你能开什么品目的发票，也决定支付通道风控怎么看你的业务 |

所以真正的时间点是：**当你需要开发票、或者流水大到被风控关注时**，去加这四项：

- 珠宝首饰零售
- 珠宝首饰批发
- 互联网销售（除销售需要许可的商品）
- 货物进出口

线上办（当地政务服务网「经营范围变更」）1~3 个工作日，线下带营业执照正副本 + 法人身份证 + 公章跑一趟。

**不用现在做。** 但记一笔：这个不是"永远不用做"，是"晚点做"。

## 7 各州销售税注册（P-01 剩余部分）

**代码已做完**：报价与订单都含税额、后台可配州税率、有申报汇总与 CSV 导出、确认信有 Tax 行。

剩下的是**纯商业 + 法务判断**：去哪些州注册、税号是多少。

### 现在的机制

美国销售税按**收货州**收，但只在某州达到 **economic nexus** 门槛后才有代收义务。常见门槛：

| 州 | 门槛（2026 口径，报税前请复核） |
| --- | --- |
| California | 年销售额 $500,000 |
| New York | 年销售额 $500,000 且 100 笔交易 |
| Texas | 年销售额 $500,000 |
| 多数中小州 | $100,000 或 200 笔交易 |

**首月正确动作：一个州都不注册，后台一个税率都不填。** 此时系统对所有州收 $0 税 —— 这是对的，不是漏了。

### 什么时候开始配

1. 每月导一次 `Sales tax` 页面的 CSV（没配税率时税额为空，但订单量是真的）
2. 盯**单州累计销售额**。任一州逼近门槛 70%，就在那个州注册
3. 拿到税号后，后台 `Settings → Sales tax` 填上，格式 `CA 7.25`（一行一州）。填完立刻生效

### 三件别做错

- **别一次性把所有州都填上**。没注册就收税 = 收了钱不交出去，比不收严重得多
- **别用"取两位字母"判断州**。`New York` 取前两位是 `NE`（Nebraska），会安静地收错州。代码里是精确匹配 + 全名归一，你正常填州名就行
- **历史订单税率是锁定的**。改税率不影响已成交订单，否则报税数字对不上

### 一句实务建议

首年别自己申报。注册 1~2 个州之后，用 TaxJar / Avalara 这类服务（约 $19~$50/月起）代报。**报错一次罚的钱够付三年服务费。**

## 8 商品实拍图（P-16）

不影响开门，影响转化率。

现在商品图是渲染图，风格统一干净，但珠宝类目的转化核心是「**戴在我身上什么样**」，不是「这个东西长什么样」。参考站 Atolea、Pura Vida 的图全是真人佩戴实拍。

### 最小可行

不用一次拍 100 款。先拍 **8~12 款主推**，每款 3 张：

1. 白底正面图（当主图）
2. 真人佩戴图（脖子 / 手腕 / 手指特写，**自然光，不要棚拍白光**）
3. 细节图（扣头、链节、石头，证明做工）

### 要求

- 正方形，至少 1600×1600，JPG
- 不加滤镜、不美颜、不 P 掉产品
- 文件名用 SKU：`LG-101-gold-01.jpg`
- 给我之后我跑 `tools/opt-img.js` 批量转 WebP

> 如果供应商能提供实拍，优先用他们的 —— 但**必须确认图是他们自己拍的**。珠宝类目盗图投诉极多，用了别人的图，下架是小，被索赔是大。
