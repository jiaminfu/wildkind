## 五、每日备份

```bash
cat /etc/cron.d/tideglass-backup
# 30 19 * * * root bash /opt/tideglass/backup.sh >> /var/log/tideglass-backup.log 2>&1
```

服务器时区是 UTC，`19:30 UTC` = 北京次日 `03:30`。

| 操作 | 命令 |
|---|---|
| 立即备份 | `bash /opt/tideglass/backup.sh` |
| 看备份列表 | `bash /opt/tideglass/backup.sh --list` |
| 恢复 | `bash /opt/tideglass/backup.sh --restore /var/backups/tideglass/db-xxx.json.gz` |
| 看备份日志 | `tail -20 /var/log/tideglass-backup.log` |

策略：保留最近 30 份（`BACKUP_KEEP`），单份约 24 KB，一年也就 9 MB。
备份脚本与仓库里的 `deploy/backup.sh` 不同——那一份假设数据在宿主机目录且宿主机装了 node，这台机器是纯容器部署、宿主机没有 node，所以数据从容器里取、用容器里的 node 校验。

**每次备份都会做 JSON 解析 + 四个关键字段校验，校验失败当场删掉，不留假备份。**

## 十、上线后登后台复查：发现的三个问题（已修并重新发布）

上线当天用真实浏览器逐模块点了一遍（不是看接口返回，是看页面），发现三个问题。三个都是"接口正常、页面不对"的类型，接口自动化 121 条全绿也发现不了。

### 10.1 登录页把默认口令印在公网上（S2）

| 项 | 内容 |
|---|---|
| 现象 | `/#/admin` 登录按钮下方一行小字：`Demo accounts — owner@tideglassjewelry.com / tideglass2026（全权限）` |
| 危害 | 站点在公网，等于把账号和默认口令挂牌公示。虽然线上口令已换成随机 18 位（`tideglass2026` 登不进），但这行字本身暴露了管理员邮箱，并引导人反复尝试 |
| 原因 | 登录页模板里写死的演示提示，本地调试方便，上线没摘 |
| 修法 | 改成中性文案 `Forgot the password? The store owner resets it on the server.`；演示账号只留在 `handover/README.md` 与服务器 `.env` |
| 验证 | 线上截图确认已无非明文口令 |

### 10.2 订单只能看到前 25 单（S2）

| 项 | 内容 |
|---|---|
| 现象 | 列表底部写着 `90 orders · page 1`，**没有任何翻页按钮**，第 26~90 单在界面上够不到 |
| 危害 | 90 单时还能靠搜索凑合；单量上千后等于后台看不到历史订单。这是"数据都在、用户够不到"的典型缺陷 |
| 原因 | 接口 `/api/v1/admin/orders` 一直支持 `page`/`limit` 并返回 `hasMore`，**前端只渲染了文字、没渲染分页条** |
| 修法 | 前端补翻页条（Prev / `N orders · page x of y` / Next），翻页时保留 `status` 与 `q` 筛选；末页 Next 置灰 |
| 验证 | 本地：page 1 → 2 → 3 → Prev 回 2，hash 依次为 `#/admin/orders?page=2/3/2`；筛选组合 `status=refunded` 显示 `8 orders · page 1 of 1` 且 Next 置灰；390px 下翻页条宽 360px、**溢出 0px** |

### 10.3 订单列表看起来是乱序（S3）

| 项 | 内容 |
|---|---|
| 现象 | 第一行是 10-25，第二行 09-08，第三行 09-20…… 店主找不到"最近一单" |
| 原因 | 真实下单用 `unshift`（新单插到数组头），插入顺序本来是对的；但**种子数据的日期是打散的**，所以演示环境看起来乱。换个角度看也是隐患：一旦有人手工改过数据文件，展示顺序就不可预测 |
| 修法 | 服务端列表统一按 `createdAt` 倒序排，谁看都是"最近的在上" |
| 验证 | 线上前 8 行日期：11-12、11-12、11-10、11-10、11-07、11-06、11-05、11-03，程序校验「是否严格倒序 = true」；接口测试 **121/121** 仍全通过 |
