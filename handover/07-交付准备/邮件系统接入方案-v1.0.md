| 邮件 | 代码 | 真实投递 | 客户现在会看到什么 |

| 订单确认 | ✅ `mail-templates.confirmed()` | ⛔ dry-run | 只有 PayPal 自己发的付款收据（英文模板、PayPal 品牌、可能进垃圾箱） |

**所以站点上那句「A confirmation is on its way to xxx@example.com」现在仍然是假的**——直到你把下面的 Key 配上。这是客户付完钱第一眼看到的东西，优先级最高。

### 1.1 代码侧已经做了什么（v1.1 补记）

| 文件 | 职责 |
|---|---|
| `app/server/lib/mail-templates.js` | 三封模板的 HTML + 纯文本双版本。**table + 内联样式**，不用 flex —— Gmail 会剥 `<head>`、Outlook 不认 flex |
| `app/server/lib/mailer.js` | Resend 直连 REST（无 SDK）。重试 3 次，**4xx 不重试**（密钥错、域名没验、收件人格式错，重试一万次也一样）；带 `Idempotency-Key`；无 Key 走 dry-run |
| `app/server/lib/notify.js` | 发信去重标记 `claim(order, field)`，写在订单的 `mail.{confirmedAt,shippedAt,refundedAt}` 上，**随事务一起落库** |

三个触发点：支付成功 / webhook paid → 确认信（两条路径靠 `claim` 去重，只发一封）；后台存运单号 → 发货信；登记退款 / webhook refunded → 退款信。

> 为什么去重要做成"事务里写标记"而不是"发送函数里判重"：确认信有两条触发路径，并发下在发送函数里判重会各判各的，结果客户收到两封。

**本地已验证**：29 项模板断言全过（字段完整性、金额格式、链接、纯文本版一致性）。**未验证**：真实投递、到达率、Gmail / Outlook 实际渲染——这三项必须等 Key。

## 2 发信服务选型

| 服务 | 免费额度 | 起步价 | 美国主流邮箱送达 | 接入复杂度 | 判 |
|---|---|---|---|---|---|
| **Resend** | 3,000 封/月（100/天） | $20/月（5 万封） | 好 | 一个 POST，无需 SDK | ⭐ 选它 |
| Postmark | 无免费 | $15/月（1 万封） | 最好（事务邮件专精） | 中 | 量上来再说 |
| Amazon SES | 无（按量 $0.10/千封） | 极低 | 好 | 高，新账号在沙盒里只能发给自己，要申请解除 | 不适合现在 |
| Brevo | 300 封/天 | $9/月起 | 一般 | 中 | 备选 |
| 阿里云/腾讯云邮件推送 | 有 | 低 | **发 Gmail/Outlook 容易进垃圾箱** | 中 | 不建议（客户全在海外） |

**选 Resend 的理由**：免费额度对初期完全够（一天 100 封 = 一天 100 单）；API 就是一个 HTTPS POST，不引入 SDK，符合项目零依赖原则；域名验证流程清晰。

**成本预期**：0 元。等到日均超过 100 单再考虑升级。

## 3 你需要做的三件事

### 3.1 注册 Resend 并拿 API Key（约 3 分钟）

1. 打开 `resend.com`，用邮箱注册（建议就用你日常看的邮箱）
2. 左侧 **API Keys** → **Create API Key**
3. 权限选 **Sending access**（不要给 Full access，发信不需要）
4. 复制生成的 key（形如 `re_xxxxxxxx`）发我

> 这个 key 只能发信、不能读你的账号，泄漏风险可控。切 Live 前我会把它写在服务器 `.env`（600 权限），不进 Git。

### 3.2 验证域名 `lastgrove.com`（约 10 分钟，含等待）

在 Resend 里 **Domains → Add Domain** → 填 `lastgrove.com` → 选择 **Cloudflare**（会自动给出记录清单）。

需要往 Cloudflare DNS 加三组记录（Resend 会给准确值，以下为形态示例）：

| 类型 | 名称 | 作用 | 是否可代理 |
|---|---|---|---|
| TXT | `resend._domainkey` | DKIM，证明邮件是你发的 | 必须 DNS only（灰云） |
| TXT | `send` | SPF，授权 Resend 代你发信 | 必须 DNS only |
| MX | `send` | 退信处理 | 必须 DNS only |

⚠️ 这三条**必须灰云（DNS only）**。橙云会让邮件验证失败——和之前 CF 525 是同一类问题。

加完回 Resend 点 **Verify**，通常 1–5 分钟生效。

### 3.3 配一个能收信的地址（可选但强烈建议）

发信人写成 `hello@lastgrove.com`，但客户点「回复」时，**这个地址现在收不到任何东西**（域名没有邮箱服务）。

最省事的解决办法（免费）：

1. Cloudflare 左侧 **Email → Email Routing**
2. 启用，创建一个自定义地址 `hello@lastgrove.com`
3. 目标邮箱填你常用的（比如 `jamie2797@outlook.com`）
4. Cloudflare 会自动加 MX 记录

这样客户回复能到你手上，且不用买企业邮箱。

## 4 我会做的部分

### 4.1 三封事务邮件

| 邮件 | 触发时机 | 内容要点 |
|---|---|---|
| **Order confirmed** | 支付真正到账（PayPal capture 成功，不是下单那一刻） | 订单号、商品清单、金额、收货地址、预计发货时间、订单查询链接 |
| **Your order has shipped** | 后台保存运单号后 | 运单号 + **可点击的承运商查询链接**（复用本次刚修好的 `U.carrierUrl`）、承运商名、订单查询链接 |
| **Refund issued** | 退款接口执行成功后 | 退款金额、原订单号、到账时间说明（3–5 个工作日）、联系邮箱 |

### 4.2 实现要点

| 要点 | 做法 | 理由 |
|---|---|---|
| 零依赖 | 用 Node 原生 `https` 调 Resend API，不装 SDK | 与现有架构一致 |
| 发信失败不阻塞业务 | 下单/发货/退款成功后再异步发信，失败只记日志 + 重试 3 次 | 邮件发不出去不能影响钱和库存 |
| 幂等 | 每封邮件带业务唯一键（如 `order-#LG1234-confirmed`），Resend 侧重复请求不会重复投递 | webhook 重投、用户刷新都可能触发第二次 |
| 模板内联样式 | 邮件客户端不支持外链 CSS / `<style>` 也不完全可靠 | 否则 Gmail 里排版全散 |
| 纯文本兜底 | 每封邮件同时给 `text` 版本 | 部分企业邮箱屏蔽 HTML 时仍可读 |
| 退订 | 事务邮件不含营销内容，不需要退订链接；但邮件底部必须有真实地址与联系邮箱 | CAN-SPAM 要求（美国法，商业邮件必须含实体地址） |

### 4.3 顺带修掉的假话

站内确认页那句「A confirmation is on its way to xxx」——邮件一旦接通，这句话就变成真的。如果暂时还没接通，应改成不承诺发信的说法。**这条会和邮件一起上，不留中间态。**

## 6 送达率注意事项（提前说，避免上线后才发现）

1. **不要用免费邮箱当发信人**。`xxx@gmail.com` 或 `xxx@outlook.com` 当 From，Gmail 会直接判伪造。
2. **第一周先小量**。新域名没有发信信誉，一天发几十封就够，别一上来群发。
3. **DMARC 用 `p=none` 起步**。等确认没有异常再收紧，一上来 `p=reject` 可能把自己的信全拒了。
4. **别在同一域名上混发营销邮件**。事务邮件（订单相关）和 newsletter 必须分开子域名或分开服务，否则一次营销投诉会拖累订单邮件送达率。
