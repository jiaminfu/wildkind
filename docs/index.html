A1站点定位与商业模式

Atolea 卖的不是"首饰"，是一个可验证的承诺：防水、不掉色、终身保色。标题、公告栏、产品页、FAQ 全部围绕这一句展开。它的品类词是 "waterproof jewelry"，而不是 "gold necklace"——这是典型的以痛点而非品类做定位，好处是转化率高、复购强，坏处是溢价天花板明显（主力价位停在 $75–$102）。

它的收入结构有三个明显的复利点，值得单独记住：①定制化（Initial / Birthstone / Name）把客单价从 $75 拉到 $95+；②订阅盒与降临历（$47.68 盲盒、$321 的 12 天礼盒）把一次性购买变成年度复购；③终身保色几乎消除了"便宜货会不会掉色"这一最大购买阻力，使它能对不锈钢材质收取接近银饰的价格。

视觉结论

这套视觉的高级感来自三个约束，而不是装饰：①只有黑白 + 一个奶油底，没有第三种彩色；②所有圆角为 0 或 2px，没有胶囊按钮（除筛选 chip）；③层次全靠字号对比与留白，不靠阴影和色块分割。重建时我们沿用这三条，但把标题字体换成 Fraunces（同为粗衬线，Google Fonts 免费，字面更柔和），把 hero 从满宽图改为左文右图以承载更多信息。

变体与徽章体系

  • 金属变体：Gold（18k PVD）为默认，Silver、14K Gold、Rose Gold 依次加价。同一款式最多 4 个色，用文字标签而非色块（文字更易搜索，也更像"材质"而非"颜色"）。
  • 徽章四类：BEST SELLER（社会证明）、LOW STOCK（稀缺）、Customizable（差异化）、Sale | SAVE $14（用绝对金额而非百分比——$14 比 16% 更有感）。
  • 定价技巧：几乎所有商品都有 compare-at price，折扣幅度固定在 $12–$39（约 15–30%），形成"常年有折扣但从不深折"的定价认知。

9礼品化礼盒、降临历、盲盒订阅采用 · 礼盒
10多轴集合一商品挂 4–6 个集合，扩大曝光面采用
11联盟分销15–20% 佣金，KOC 大量铺量二期
12满屏弹窗首访弹 10% off 邮箱收集不做

第 12 条为什么不做

弹窗能提升 3–5% 的邮箱收集率，但会让首屏 LCP 变差、移动端跳出率上升。对单人团队来说，邮件列表的价值低于首单转化率。我们改用页脚订阅 + 订单后订阅，把收集成本放到用户已经付钱之后。

A7学什么 / 不学什么

必须学

  • 单一承诺：一个能被验证的承诺（防水不掉色），而不是四个形容词
  • 11 项一级导航全平铺：让用户两步内到达任何品类，减少点击成本
  • 用 tag 做集合：一件商品挂多个入口，靠运营而非开发扩曝光
  • 绝对金额折扣：SAVE $16 比 -20% 直观
  • 材质叙事：把 316L + PVD 讲成技术优势，支撑 $62 的不锈钢项链
  • 定制线：Initial / Birthstone 是最低成本的 AOV 提升手段

不学 / 要改

  • 满宽 hero 纯图：信息密度太低，第一屏没讲清"卖什么、多少钱、为什么信你"
  • 4 种金属变体：单人库存压力大，我们只做 Gold + Silver 两色
  • 常年全站折扣：会训练用户等折扣，我们只在季末做两次
  • 订阅盒：供应链与选品复杂度远超单人产能，二期再评估
  • 15 种货币：只做 USD，减少支付与定价复杂度
  • 账户体系：访客下单 + 订单号查询，砍掉注册流失

我们的差异化落点

Atolea 的题材是"地名 + 极简几何"（Ios、Saona、Positano），我们做的是具体动植物与天体——狐狸、野兔、海龟、蕨类、月相。这在搜索端有天然优势（"fox necklace"、"sea turtle jewelry" 是明确的长尾词），在内容端可讲故事（每种动物一段来源）。代价是设计成本更高：每款要重新造型，不能靠改链子长度出新 SKU。这正是护城河所在——Atolea 的模式可以被任何人复制，具体造型的原创性不能。

1概述与范围

1.1 项目背景

Wildkind 是面向北美市场的自然主题不锈钢饰品品牌，单人运营，供应链位于东莞长安（距深圳工作室 40 分钟），履约通过美国俄勒冈州 3PL 完成。现有站点的核心问题不是缺功能，而是信息架构不成体系：一级分类按"手链/项链"平铺，但缺少风格、寓意、送礼对象三条正交维度，导致同一件商品只能被一个入口命中，曝光面被压缩。

本项目的目标是用一套对齐行业最优解（Atolea Jewelry）的信息架构，重建前台购物流程与后台运营系统，使一个人可以在 30 分钟内完成每日运营（看数据、处理订单、补库存、改文案）。

设计决策：为什么不做账户体系

账户注册在 DTC 首饰类目的转化损失约 8–12%，而收益只有"订单历史"这一项。本项目的替代方案是订单号 + 邮箱双因子查询：安全强度足够（两者组合不可枚举），且下单流程少一步。代价是无法做积分与个性化推荐——这两个能力在 M3 之后按需补。

4.1 全局导航与搜索

1架构总览

系统采用服务端渲染 + 轻量客户端增强的分层架构。前台每个页面由服务端拼装完整 HTML 返回（利于首屏与 SEO），交互部分（购物车、筛选、手风琴）由约 250 行原生 JS 接管；后台是单页应用，通过 REST 接口读写数据。原型阶段数据落在单个 JSON 文件，生产阶段替换为 PostgreSQL，上层代码不需要改动结构。

1.1 关键设计取舍

决策选择理由与代价
渲染方式服务端渲染 HTML首屏快、SEO 友好、无需构建。代价：页面切换是全量刷新，交互感弱于 SPA
后台形态客户端 SPA表格筛选、弹窗编辑需要频繁局部更新。代价：首屏需等一次接口
数据存储JSON 文件 + mtime 缓存零依赖、可读、可直接 diff。代价：无并发控制，不适合多人同时写
样式方案原生 CSS + CSS 变量体积极小、无工具链。代价：无作用域隔离，需靠命名约定
购物车存储Cookie（base64 JSON）无需服务端会话、跨页保持、30 天有效。代价：容量上限 4KB，约 20 行
图表手写 SVG无图表库依赖、完全可控、可打印。代价：交互能力有限

为什么原型不用 Next.js

原型的目标是让非技术方能在 5 秒内看到全部页面与后台真实交互。引入 Next.js 需要安装依赖、构建、处理版本兼容，而这些成本不产生任何产品价值。原生 Node 方案零安装即可运行，评审者双击 start.bat 就能看到完整系统。生产阶段再迁移，迁移路径已在第 10 章给出。

为什么 items 内嵌而不独立成表

订单是不可变事实：商品下架、改价、改名之后，历史订单必须保持原样。因此 items 存的是成交瞬间的快照（title / price / cost 全部冗余），而不是外键连接。这样即使商品被删除，订单仍可完整回放。代价是存储冗余——但在订单量级 < 100 万的阶段，这个代价可以忽略。

6.2 库存扣减一致性

原型采用「读 → 改 → 写」的简单模型，扣减逻辑为 stock = max(0, stock − qty)，因此不会出现负库存，但两个并发请求可能丢失一次扣减（写覆盖）。这在本阶段有意接受——单人运营不存在并发下单。

生产阶段改为数据库事务 + 行级锁：

BEGIN;
  UPDATE products SET stock = stock - $qty
   WHERE id = $id AND stock >= $qty
  RETURNING stock;
  -- affectedRows = 0 表示库存不足，回滚并返回 409
  INSERT INTO orders (...) VALUES (...);
COMMIT;

6.3 财务指标计算

看板的全部数字来自 summary(days) 一次聚合，不依赖任何预计算表。核心逻辑：

// 单笔订单
cogs        = Σ(item.cost × item.qty)
duty        = cogs × 0.31              // 中国产地仿首饰综合税负
freight     = cogs × 0.055             // 头程与清关分摊
fulfillment = 9.80                     // 3PL 仓配 + 尾程（每单固定）
fees        = total × 0.029 + 0.30     // Stripe
packaging   = 0.85
returns     = total × 0.06             // 退货计提

cost   = cogs + duty + freight + fulfillment + fees + packaging + returns
profit = total − cost
margin = profit / total

// 区间汇总
revenue    = Σ(paid + fulfilled 订单的 total)
refundRate = refunded 订单数 / 区间订单总数
repeatRate = 多单客户数 / 有效客户数
weeksCover = 在库件数 / (区间售出件数 / 天数 × 7)

最容易做错的一处

多数看板把「毛利率」算成 (售价 − 工厂成本) / 售价，会得出 88% 这种假数字。真实的贡献毛利必须扣除关税（31%）、头程、仓配（$9.8/单）、支付费（3.2%）、包装与退货计提。同样一款 $62 的项链，两种算法分别是 88% 与 62%——相差 26 个点，足以让一个错误的定价决策发生。
