怎么用这份原型说明

它不是最终视觉，也不连数据。用途只有一个：在写代码之前，把"长什么样、怎么走"定下来。

建议的评审顺序

  1. 先看首页与集合页：确认信息架构和商品卡的信息密度是否合适。
  2. 再看详情与购物车：确认变体、库存提示、加购反馈的交互是否顺手。
  3. 然后看结算：确认分几步、要填多少字段——这一步直接决定转化率。
  4. 最后看后台四屏：确认你日常操作够不够快，有没有缺常用动作。

请重点给这几处意见

  • 首页九个区块是否太多？哪几块可以砍掉？
  • 商品卡上要显示的信息够不够、会不会太挤？
  • 结算是否要拆成两步（先信息后支付）？
  • 后台是否需要「定制需求单」独立模块？
  • 移动端首页的模块顺序是否要调整？

边界说明

灰色斜纹块 = 图片位置；灰条 = 文字；细线框 = 输入框或按钮。真正的颜色、字体、图片质感会在视觉方案里给，不在这份原型里。
