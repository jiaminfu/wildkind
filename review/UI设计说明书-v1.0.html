1设计原则

上一版界面被判"太乱"，根因不是配色或审美，是没有刻度：全站用过 36 种字号（8px 到 72px，其中 9.5/10/10.5/11/11.5/12/12.5px 各出现二十多次）、间距随手写、容器层级混乱。没有刻度，每个区块看起来就像不同人做的。

这一版只立四条规则，全部可量化：

#原则具体约束违反时的表现
1一把尺子字号只用 8 级，间距只用 8px 基数，字体只用 2 族页面"看起来乱"但说不出哪乱
2三层容器页面底（cream）→ 内容面（paper）→ 强调块（sea），不允许第四层区块之间没有边界，用户不知道哪里是新的一段
3一个页面一个主角每屏只有一个元素可以用最大字号或最深色块所有东西都在喊，等于没人被看见
4克制用色Clay 红只表示降价 / 出错 / 危险；深绿只做品牌与主操作Sale 标签失去警示力，用户对红色脱敏
为什么把"乱"翻译成数字：审美无法验收，刻度可以。"这个页面有 43 种字号"是能测出来的，"这个页面不好看"没法争论出结果。所以这套规范全部写成可校验的数值，评审时对着量即可。

--t5 · 20px / 1.3Card title / 价格大字
--t4 · 16px / 1.55导语与强调正文
--t3 · 14px / 1.6正文默认（body 基准）
--t2 · 12px / 1.5辅助信息、按钮文字
--t1 · 11px / 1.4导航 / 标签 / 眉标
层级字号字族字距用在哪
H1 首屏主标题40–56衬线-.02em仅首屏，全站只有一处
H2 区块标题28衬线-0.005em各内容区块
H3 卡片标题20衬线0商品名、文章标题
Body 正文14无衬线.005em全站基准
Nav / Label11–12无衬线.14em 大写导航、标签、按钮、眉标
价格14–20无衬线等宽数字0必须开 tabular-nums，否则金额列会跳
为什么是这 8 级而不是更细：11 与 12 差 1px，在 14px 正文旁边几乎无法分辨，但会让代码里出现"这里到底该用 11 还是 12"的争论。刻度少一级，团队少一次讨论。需要区分时用字重、颜色、字距，不用字号。

2.3 间距（8px 基数）

--sp1 · 4图标与文字之间
--sp2 · 8标签内边距、紧凑行距
--sp3 · 12表单行间距
--sp4 · 16卡片内边距（小）
--sp5 · 24卡片内边距（标准）
--sp6 · 32区块内元素间距
--sp7 · 48区块之间
--sp8 · 64大区块之间
--sp9 · 88页面首尾留白

规则：任何 margin / padding 只能取这 9 个值。设计稿上量出 18px，写 16 而不是 18——这 2px 的差异肉眼不可见，但它会让间距体系失去一致性。

2.4 三层容器

底 · Cream#FAF6EF
页面背景、区块背景
面 · Paper#FFFFFF
卡片、表单、表格、抽屉
块 · Sea#1B3A34
页脚、主 CTA、强调条

层次靠这三层的明度差建立，不靠阴影。规则：

  • 同一屏内不出现同层叠同层（paper 上再放 paper 卡片，边界会消失）。
  • 需要第三层时用 --sand 或加描边，不引入第四种底色。
  • 深色块（sea）在一个页面里最多两处，且不能相邻——否则页面重心分裂。

2.5 描边、圆角、阴影

项值规则
圆角0 / 2px全站几乎不用圆角。2px 只用于输入框与标签，卡片与按钮直角。圆角是"软萌"语言，与品牌的"旧物感"冲突
描边1px --line所有容器靠描边分界，不靠阴影
阴影--shadow-s 0 1px 2px rgba(22,19,15,.05)
--shadow-m 0 10px 30px rgba(22,19,15,.08)		只有两类元素用阴影：① 浮层（抽屉、搜索浮层、下拉）用 m；② 极少数需要抬起的卡片用 s。列表里的卡片一律不加阴影
分割线1px --line2（#F0EAE0）比描边更淡，用于同一容器内的行分隔

2.6 图标

  • 线性图标，1.5px 描边，24×24 视框，圆头端点。
  • 尺寸只用两种：页头 17px、内容区 20px。禁止混用 18 / 22 这类中间值。
  • 图标必须配文字或 aria-label，不单独承担语义（购物袋除外）。
  • 图标颜色跟文字走（currentColor），不单独设色，避免出现"深绿文字配灰色图标"。

文字规则：全大写 + .14em 字距 + 500 字重。按钮文案不超过 3 个词，超过改用 Ghost 或缩写成动词。

3.2 标签（Badge）

New Best Seller Sale Only 3 left

规则：① 一张商品卡最多 2 个标签；② 优先级 SALE > LIMITED > NEW；③ Sale 用 clay 实底，其余描边；④ 标签不用阴影（阴影会让它在图片上"浮起来"，显得廉价）。

3.3 表单

Email address wrong@format
状态表现规则
默认1px --line 描边，白底，44px 高不自带圆角阴影
聚焦描边变 --sea + --focus-ring不改变尺寸（避免布局跳动）
错误描边 --clay，下方 12px 错误文案提示语必须说"怎么改"，不写"输入有误"

3.4 商品卡

Foxtrot Pendant$82.00 $102
Add to bag
  • 结构：主图（1:1）→ 悬停换次图 → 标题（14px，单行截断）→ 价格（现价 + 划线价）→ 加购按钮（Small，hover 才出现，触屏常驻）。
  • 图与文字间距 --sp3；标题与价格间距 --sp1。
  • 不在卡片上重复显示 SAVE $X——角标已经说明，价格行的划线价已经说明，第三次重复是噪音。

3.6 其他组件要点

组件关键规则
抽屉（购物车）右侧滑出 420px；蒙层 rgba(22,19,15,.38)；打开时锁背景滚动；Esc 与点蒙层关闭

4页面规范

逐页给出「主角 / 层次 / 关键尺寸」，避免每页重新发明一遍。

页面主角层次结构关键尺寸
首页首屏大标题 + 轮播图首屏（cream）→ 横滑商品（cream）→ 数字背书（sea 条）→ 题材磁贴 → 故事（cream+图）首屏高度 82vh；标题 56px；区块间距 88px

后台数据左侧导航（220px，sea 底）+ 顶栏 + 内容区（cream）表格行 48px；卡片内距 20px

5响应式

断点宽度关键变化
桌面≥ 1280完整导航 11 项；商品 4 列；结算两栏
平板768–1279导航收为汉堡；商品 3 列；结算两栏但右栏收窄
移动< 768导航全收；商品 2 列；结算单栏（摘要置顶或折叠）；页头必须保留账户图标（FR-S-152）

三条硬性检查（每次改版都要过）：

  1. 任何宽度下不出现横向滚动（document.documentElement.scrollWidth <= clientWidth）。
  2. 触控目标 ≥ 44×44px（加购、关闭、数量步进）。
  3. 正文在任何宽度下不小于 14px——移动端常见错误是把字号压到 12px 塞进更多内容。

6交互与动效

场景时长缓动说明
hover 变色180msease只变颜色，不变尺寸
抽屉滑出320mscubic-bezier(.22,.61,.36,1)出快进慢，收尾有停顿感
状态切换（tab / 手风琴）220msease高度动画不超过 300ms，否则显得迟钝
图片淡入400msease-out懒加载图淡入，避免"突然出现"
Toast200ms 进 / 停留 3sease最多同时 2 条
动效只用来说明"什么变了"，不用来装饰。判断标准：把动画去掉，用户是否还能理解发生了什么？如果能，这个动画就不该有。首页英雄图的自动轮播是例外（它承担内容轮换职责），但必须可关。

7无障碍

项要求校验方式
对比度正文 ≥ 4.5:1；大字（≥18px 或 14px 粗体）≥ 3:1浏览器取色计算；--glass 不可用于正文（对 cream 只有 2.1:1）
键盘Tab 可走完全流程（加购 → 结算 → 支付）；焦点始终可见拔掉鼠标走一遍
焦点样式统一 outline:2px solid var(--sea); outline-offset:3px不用 outline:none
图片装饰图 alt=""；商品图 alt 写"商品名 + 视角"禁用图片后仍能理解页面
表单每个输入有 label 关联；错误用 aria-live 播报屏幕阅读器测试
动效尊重 prefers-reduced-motion，关闭轮播与滑出动画系统开启后检查
触控点击区 ≥ 44×44px移动端逐一点

8验收清单

设计交付前逐条打勾。这 12 条全部机械化，不需要审美判断：

#检查项通过标准
1字号种类全站 ≤ 8 种（grep -o "font-size:[0-9.]*px" | sort -u | wc -l）
2间距种类全部落在 4/8/12/16/24/32/48/64/88 之内
3字体族衬线 1 + 无衬线 1，共 2 个
4底色种类cream / paper / sand / sea 四种，不出现第五种
5Clay 用色只出现在 Sale 价、错误、删除三处
6每屏主角每屏只有一处最大字号 / 深色块
7横向滚动375 / 768 / 1440 三个宽度均为 0
8触控目标移动端所有可点元素 ≥ 44px
9对比度正文 ≥ 4.5:1
10键盘流程Tab 可完成一次加购到支付
11图片 alt所有 <img> 有 alt 或明确装饰标记
12功能回归改样式后 e2e.js 与 e2e-flow.js 全绿（样式改动不得影响交互）
第 12 条最重要。上一轮改 UI 时就出现过一次：样式调整把某个类名改了，结算步骤条被撑成 151px 高、文案居中错位，而功能测试照样全绿——因为测试只检查元素存在，不检查布局。所以样式改动的验收必须包含"功能回归 + 逐页视觉复核"两件事，缺一不可。
