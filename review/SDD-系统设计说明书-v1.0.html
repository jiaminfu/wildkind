1文档说明

本文回答"这套系统怎么搭、数据怎么存、接口怎么定、上线放哪里、出问题怎么查"。所有关键决策都给出选项对比 + 建议 + 待确认标记，不默认你已经同意某一个方案。

与 FRD 的关系：FRD 定义"做什么"，本文定义"怎么做"。凡是本文出现的技术选择，若与你的预期冲突，以你的确认为准，改文档成本远低于改代码。

2.2 两个前端形态

形态使用方渲染方式为什么这样选
前台商城消费者服务端渲染（SSR）+ 少量客户端脚本商品页要能被 Google 收录，首屏要快；交互只在加购、抽屉、筛选处增强
后台管理你 / 运营单页应用 + JSON API不需要 SEO，追求操作不刷新、切页快

两者共用同一套领域逻辑与数据库，避免"前台一套规则、后台一套规则"导致数据对不上——这是上一版最需要避免的问题。

3技术选型

3.1 三个候选方案

方案构成优点代价适合场景
A（建议）
自建全栈		 Next.js + Prisma + PostgreSQL + Stripe + Resend，部署在 Coolify 完全可控、无平台抽成、结构随意扩展、SEO 友好 需要自己维护服务器与备份 长期做品牌、SKU 会持续增加
B 轻量自建 Node 原生服务 + 单文件 JSON 存储 极轻、启动快、零依赖、改起来最快 并发与数据量上限低；多人同时改易冲突 纯演示 / 内部评审 原型阶段用过
C 平台托管 Shopify + 主题定制 交易、支付、物流生态成熟，几乎不用写代码 月费 + 交易抽成；深度定制受限；数据不在自己手里 想最快开店、不打算做特殊流程
建议：A。理由：你的 100 款 SKU 与多轴集合体系需要自定义数据结构；后台的成本拆解、定制单这类需求平台方案做不了；长期看自建的可控性更重要。若你更看重"最快上线"，C 也成立，但要接受抽成与定制上限。

5.3 两个关键设计决定

  • 订单项存快照：下单时把标题、价格、变体、成本写入 OrderItem，之后商品改价不影响历史订单与毛利核算。
  • 客户以邮箱为主键：不做账户体系时，邮箱是唯一可用的身份锚点；同一邮箱多次下单聚合为同一客户，用于复购统计。

6.3 约定

  • 统一响应体：{ ok, data, error }；错误带 code 与可读 message。
  • 金额一律用整数分存储与传输，避免浮点误差。
  • 后台接口全部要求会话；写操作校验 CSRF Token；列表接口强制分页（默认 20，上限 100）。
  • 幂等：/api/checkout/intent 与 webhook 以 idempotencyKey / 事件 id 去重，防止重复建单。

7关键流程

7.1 下单与扣库存

1 提交
校验地址与库存计算运费与税创建 pending 订单
2 支付
创建 PaymentIntent用户在 Stripe 内嵌表单支付
3 回调
校验签名 + 事件去重订单转 paid扣减库存
4 通知
发确认邮件写入 StatusLog后台出现待配货

失败路径：支付失败 → 订单保持 pending → 30 分钟后自动关闭并释放占用；回调重复 → 按事件 id 丢弃，不重复扣库存。

7.2 发货与退款

  • 后台填运单 → 订单转 fulfilled → 发发货邮件（含物流号）→ 客户可用订单号查单。
  • 退款：后台登记退款申请 → 二次确认 → 调 Stripe 退款 → 订单转 refunded → 发退款邮件 → 库存是否回补由人工决定（默认不回补，避免二次销售瑕疵品）。

项方案说明

9安全与合规

面措施
后台鉴权密码哈希（bcrypt/argon2）、HttpOnly + SameSite Cookie、会话 24h、登录失败限流与锁定
输入服务端全量校验；富文本白名单过滤；上传限类型与大小
CSRF / XSS写操作校验 Token；输出转义；CSP 限制外链脚本
支付Stripe 托管卡信息，服务端只存支付意图 id 与结果，不落卡号（PCI 责任转移）
隐私只收集履约必需信息；隐私政策与删除通道；Cookie 同意后才加载分析
合规GDPR / CCPA（同意、访问、删除）；IOSS 与关税展示（待确认具体国家）
数据全链路 HTTPS；备份加密；敏感配置走环境变量不入库不入 Git
审计后台关键动作写操作日志（改价、改库存、退款）

10性能与缓存

  • 页面：商品页与集合页 SSR 后做短时缓存（60s）+ 内容变更时主动失效。
  • 图片：统一 4:5，输出 3 档宽度（480 / 900 / 1400），WebP 优先，懒加载首屏以下。
  • 数据库：列表查询走索引；后台统计用按日聚合表，避免每次全表扫描。
  • 前端：首页 JS 体积控制在 100KB 以内；图表用轻量 SVG 自绘，不引大库。
  • 指标：LCP ≤ 2.5s、CLS ≤ 0.1、TTFB ≤ 500ms（目标值，验收时实测）。

12风险与对策

风险影响对策
支付回调丢失已付款但订单未转 paid定时对账任务，按 Stripe 会话反查并补单
超卖客户付款后无货支付成功时事务内扣减，扣失败自动退款并告警
图片体积过大首屏慢、转化下降上传即转码，限制源图尺寸
单机故障全站不可用每日备份 + 镜像化部署，30 分钟内可重建
合规披露不全被投诉 / 支付通道风控上线前逐项核对政策页与 Cookie 同意
